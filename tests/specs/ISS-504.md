# ISS-504 Test Specification: Per-Tenant Migration Tracking

## Requirement
ISS-504: Reconcile schema + per-tenant migration tracking (SPT-04)

## Test Cases

### TC-ISS504-01: GBL- migrations recorded with schema_name='public'
- **Layer:** Integration
- **Precondition:** GBL- migrations applied
- **Steps:**
  1. Query public.schema_migrations WHERE schema_name='public'
  2. Verify GBL- migrations present
- **Expected:** All GBL- migrations have schema_name='public'. No GBL- migration has schema_name != 'public'.

### TC-ISS504-02: Per-tenant migrations recorded with schema_name='tenant_{slug}'
- **Layer:** Integration
- **Precondition:** Tenant provisioned with SCHEMA storage mode
- **Steps:**
  1. Query public.schema_migrations WHERE schema_name='tenant_{slug}'
  2. Verify non-GBL migrations present
- **Expected:** Non-GBL migrations have correct schema_name. No GBL- migration has schema_name='tenant_{slug}'.

### TC-ISS504-03: Provisioning records per-tenant migration state
- **Layer:** Integration
- **Precondition:** New tenant provisioned
- **Steps:**
  1. Provision a new tenant
  2. Check public.schema_migrations for entries with schema_name = tenant schema
  3. Check tenant_schemas.migrations_applied_at IS NOT NULL
- **Expected:** Migration entries exist. migrations_applied_at is set.

### TC-ISS504-04: ADP-12 default-tenant regression with SCHEMA mode
- **Layer:** Integration
- **Precondition:** Default tenant provisioned in SCHEMA mode
- **Steps:**
  1. Run ADP-12 test suite against default tenant
  2. Verify all CRUD operations work through SCHEMA routing
- **Expected:** All ADP-12 tests pass. No RLS-dependent behaviour.
