# ISS-503 Test Specification: RLS Removal

## Requirement
ISS-503: Remove legacy tenant_id/RLS predicates (SPT-03)

## Test Cases

### TC-ISS503-01: GBL-084 pre-flight blocks when LEGACY_RLS tenants exist
- **Layer:** Integration
- **Precondition:** At least one tenant with storage_mode='LEGACY_RLS'
- **Steps:**
  1. Attempt to apply GBL-084 migration
  2. Observe result
- **Expected:** Migration fails with EXCEPTION. Migration not recorded in schema_migrations. No DDL changes applied.

### TC-ISS503-02: GBL-084 succeeds when zero LEGACY_RLS tenants
- **Layer:** Integration
- **Precondition:** All tenants have storage_mode='SCHEMA'
- **Steps:**
  1. Apply GBL-084 migration
  2. Check RLS policies, tenant_id columns, function
- **Expected:** Migration succeeds. All RLS policies dropped. All tenant_id columns dropped from business tables. bpm_effective_tenant_id() dropped. Migration recorded in schema_migrations.

### TC-ISS503-03: GBL-084 is idempotent
- **Layer:** Integration
- **Precondition:** GBL-084 already applied
- **Steps:**
  1. Re-apply GBL-084
  2. Check for errors
- **Expected:** Migration succeeds (IF EXISTS no-ops). No errors.

### TC-ISS503-04: SCHEMA-path requests work after RLS removal
- **Layer:** Integration
- **Precondition:** GBL-084 applied, all tenants SCHEMA
- **Steps:**
  1. Authenticate and make CRUD requests
  2. Verify no RLS-related errors
- **Expected:** All requests succeed. No references to bpm.tenant_id in query plans.
