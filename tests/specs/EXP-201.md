# Test Spec: EXP-201 — Entity Definition Format

## Description
Verify entity definition JSON parsing and validation. Each definition must follow the schema and rules defined in `src/design/entities.md`, including field name format, uniqueness, and the `queried + json` exclusion rule.

## Covered Requirements
- EXP-201: Entity definition format
  - EXP-201-1: Name format (`[a-z][a-z0-9_]*`)
  - EXP-201-2: Field uniqueness
  - EXP-201-3: `queried + json` exclusion rule
  - EXP-201-4: Index field coverage
  - EXP-201-5: FK field coverage
  - EXP-201-6: Enum/Decimal validation
  - EXP-201-7: Cardinality limits (fields, indexes, FKs)

## Test Cases

### TC-EXP-201-01: Valid Entity Definition
- **Description:** Successfully create a valid entity definition with various field types.
- **Input:** 
  ```json
  {
    "name": "customer",
    "display_name": "Customer Profile",
    "fields": [
      { "name": "email", "type": "text", "required": true, "queried": true },
      { "name": "age", "type": "integer", "queried": true },
      { "name": "metadata", "type": "json" }
    ]
  }
  ```
- **Expected Outcome:** `Validator.validateDefinition` returns `void`. `EntityDefinition.createDefinition` succeeds.

### TC-EXP-201-02: Invalid Entity Name
- **Description:** Reject entity names that do not match `[a-z][a-z0-9_]*`.
- **Input:** `{"name": "Invalid-Name", ...}`
- **Expected Outcome:** Error `InvalidNameFormat`.

### TC-EXP-201-03: Duplicate Field Names
- **Description:** Reject definitions with overlapping field names.
- **Input:** 
  ```json
  {
    "name": "customer",
    "fields": [
      { "name": "email", "type": "text" },
      { "name": "email", "type": "text" }
    ]
  }
  ```
- **Expected Outcome:** Error `FieldNameConflict`.

### TC-EXP-201-04: Queried + JSON Exclusion Rule
- **Description:** Verify that a field cannot be both `queried: true` and `type: "json"`.
- **Input:** 
  ```json
  {
    "name": "order",
    "fields": [
      { "name": "raw_payload", "type": "json", "queried": true }
    ]
  }
  ```
- **Expected Outcome:** Error `FieldQueriedAndJson`.

### TC-EXP-201-05: Missing Enum Values
- **Description:** Reject enum fields without a list of allowed values.
- **Input:**
  ```json
  {
    "name": "user",
    "fields": [
      { "name": "status", "type": "enum", "validation": {} }
    ]
  }
  ```
- **Expected Outcome:** Error `MissingEnumValues`.

### TC-EXP-201-06: Invalid Decimal Spec
- **Description:** Reject decimal fields without precision or scale.
- **Input:** `{"name": "price", "type": "decimal", "validation": {"precision": 10}}` (missing scale)
- **Expected Outcome:** Error `InvalidDecimalSpec`.

### TC-EXP-201-07: Index Field Not Queried
- **Description:** Reject indexes referencing non-queried fields.
- **Input:** `{"name": "e", "fields": [{"name":"f", "type":"text", "queried":false}], "indexes": [{"name":"idx", "fields":["f"]}]}`
- **Expected Outcome:** Error `IndexFieldNotQueried`.
