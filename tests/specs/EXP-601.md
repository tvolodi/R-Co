# Test Spec: EXP-601 - Tier-to-Quota Central Enforcement Model

**Requirement:** EXP-601 - Central tier-to-quota enforcement in kernel middleware.
**Priority:** MUST
**Test layer:** integration

## Test Cases

### TC-EXP-601-01: quota policy resolves the effective profile from the active config surface
**Given:** a tenant with an active `tier_quota_policy` config artifact and another tenant without one
**When:** the quota policy resolver loads the effective profile for each tenant
**Then:** the tenant with an active artifact receives the configured limits, while the tenant without an artifact still resolves successfully via the default tier profile
**Layer:** integration
**Acceptance criterion mapped:** limits live in one config surface; policy resolution is tenant-scoped and centralized

### TC-EXP-601-02: quota middleware rejects entity writes when entity limits are exceeded
**Given:** a tenant whose active quota policy sets entity limits to zero and a tenant-scoped projection row exists
**When:** the quota middleware evaluates an entity-write request that requests one additional unit
**Then:** the middleware returns a rejected result with HTTP 429 and a quota problem body that identifies the entity quota dimension
**Layer:** integration
**Acceptance criterion mapped:** exceeding a tenant quota is rejected centrally across quota dimensions

### TC-EXP-601-03: quota middleware rejects file writes when file limits are exceeded
**Given:** a tenant whose active quota policy sets file limits to zero and a tenant-scoped artifact row exists
**When:** the quota middleware evaluates a file-write request that requests one additional unit
**Then:** the middleware returns a rejected result with HTTP 429 and a quota problem body that identifies the file quota dimension
**Layer:** integration
**Acceptance criterion mapped:** centrally enforced quota rejection across quota dimensions

### TC-EXP-601-04: quota middleware rejects sandbox allocation and agent retries through the same guard path
**Given:** a tenant whose active quota policy sets sandbox and retry limits to zero and real usage rows exist
**When:** the quota middleware evaluates sandbox-allocation and retry requests that request one additional unit
**Then:** the middleware returns rejected results for both targets, with 429 problem responses from the same enforcement module
**Layer:** integration
**Acceptance criterion mapped:** kernel middleware centralization and single enforcement surface

### TC-EXP-601-05: quota target classification maps supported write routes and rejects unsupported or read-only requests
**Given:** a set of representative request paths and methods
**When:** the classification helper maps each request to a quota target
**Then:** supported write paths map to the expected guard target, while read-only or unknown paths return no target
**Layer:** integration
**Acceptance criterion mapped:** middleware gate is applied before handler work using a centralized target classifier
