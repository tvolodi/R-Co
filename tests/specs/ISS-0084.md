## 1. Test Objective

Verify that `assertDatabaseConfiguration()` detects database misconfiguration at startup and emits the exact FATAL log line format required for alert routing.

---

## 2. Test Environment Requirements

- Real PostgreSQL instance (via `BPM_TEST_DB_URL`)
- Ability to manipulate test database state:
  - Drop/install extensions (`pg_trgm`)
  - Create/drop tables in `public` schema
  - Optionally: spin up an old PostgreSQL version container (13.x) for version mismatch test
- Stderr capture mechanism (see section 4)

---

## 3. Test Cases

### 3.1 Success Path

**Test Name:** `assertDatabaseConfiguration_success`

**Preconditions:**
- PostgreSQL 14.0 or later
- `pg_trgm` extension installed
- `public` schema has 0 application tables (only system tables allowed)

**Action:**
```zig
const result = try startup_assertions.assertDatabaseConfiguration(testing.allocator, &pool);
```

**Expected Result:**
- Returns `void` (no error)
- No FATAL log line emitted
- Connection pool remains healthy

---

### 3.2 Version Mismatch

**Test Name:** `assertDatabaseConfiguration_version_too_old`

**Preconditions:**
- PostgreSQL 13.x (or mock `current_setting('server_version_num')` to return `130008`)

**Action:**
```zig
const result = startup_assertions.assertDatabaseConfiguration(testing.allocator, &pool);
```

**Expected Result:**
- Returns `error.PgVersionMismatch`
- FATAL log line emitted to stderr:
  ```
  FATAL startup.database PG_VERSION_MISMATCH current=130008 required_min=140000
  ```
- Exact string match assertion (see section 4)

**Implementation Note:** If spinning up a PG 13.x container is too complex for CI, mock the version check by:
1. Creating a test-only variant of `assertDatabaseConfiguration` that accepts a `version_override` parameter, OR
2. Using a temporary `SET` statement to override `server_version_num` (not possible — it's read-only)
3. Preferred: use a separate PG 13.x container for this one test, controlled by a fixture script

---

### 3.3 Extension Missing

**Test Name:** `assertDatabaseConfiguration_extension_missing`

**Preconditions:**
- `DROP EXTENSION IF EXISTS pg_trgm;` executed on test database

**Action:**
```zig
const result = startup_assertions.assertDatabaseConfiguration(testing.allocator, &pool);
```

**Expected Result:**
- Returns `error.PgExtensionMissing`
- FATAL log line emitted to stderr:
  ```
  FATAL startup.database PG_EXTENSION_MISSING extension=pg_trgm
  ```
- Exact string match assertion

**Cleanup:**
```zig
defer {
    // Restore pg_trgm for other tests
    pool.execute("CREATE EXTENSION IF NOT EXISTS pg_trgm;");
}
```

## 4. FATAL Line Capture Mechanism

### 4.1 Approach 1: Stderr Redirect (preferred for determinism)

```zig
test "assertDatabaseConfiguration_version_too_old" {
    var stderr_buffer = std.ArrayList(u8).init(testing.allocator);
    defer stderr_buffer.deinit();
    
    // Redirect stderr to capture buffer
    const original_stderr = std.io.getStdErr();
    defer std.io.setStdErr(original_stderr);
    
    var stderr_writer = stderr_buffer.writer();
    std.io.setStdErr(std.io.Writer{ .context = &stderr_writer, .writeFn = ... });
    
    // Arrange
    const pool = try setupTestPoolWithOldPostgres();
    defer pool.deinit();
    
    // Act
    const result = startup_assertions.assertDatabaseConfiguration(testing.allocator, &pool);
    
    // Assert
    try testing.expectError(error.PgVersionMismatch, result);
    
    const stderr_text = stderr_buffer.items;
    const expected_line = "FATAL startup.database PG_VERSION_MISMATCH current=130008 required_min=140000";
    try testing.expect(std.mem.indexOf(u8, stderr_text, expected_line) != null);
}
```

**Trade-offs:**
- ✅ Deterministic — captures exactly what `obs_logger` emits
- ⚠️ Platform-specific — Zig's `std.io.setStdErr` API may differ on Windows vs Linux
- ⚠️ Brittle if logger adds timestamps or thread IDs to the line

### 4.2 Approach 2: Test-Only Logger Hook (alternative)

Modify `obs/logger.zig` to expose a test-only capture hook:

```zig
// In obs/logger.zig (TEST-DESIGNER decision):
var test_log_capture: ?*std.ArrayList(u8) = null;

pub fn setTestCapture(buffer: *std.ArrayList(u8)) void {
    test_log_capture = buffer;
}

pub fn log(...) {
    // Existing stderr write
    // PLUS:
    if (test_log_capture) |buf| {
        buf.appendSlice(formatted_line);
    }
}
```

**Trade-offs:**
- ✅ More portable (no OS-level stderr redirect)
- ⚠️ Pollutes production logger with test code (mitigate with `@import("builtin").is_test` guard)
- ✅ Easier to filter exact log lines (avoid timestamps)

**Recommendation:** Defer decision to TEST-DESIGNER. Both are valid. Approach 1 is more realistic (tests what actually goes to stderr in prod). Approach 2 is more maintainable.

## 5. Test Fixture Requirements

### 5.1 Per-Test UUID Isolation

All test fixtures must use per-test UUIDs for tenant IDs, table names, or other identifiers to avoid cross-test pollution.

**Not applicable here:** This module does not create tenant-scoped data. Tests interact only with the `public` schema and global settings.

### 5.2 Cleanup

Every test that modifies database state (e.g., drops an extension, creates a table) MUST restore it in a `defer` block to avoid affecting subsequent tests.

**Example:**
```zig
test "assertDatabaseConfiguration_extension_missing" {
    const pool = try setupTestPool();
    defer pool.deinit();
    
    // Arrange: remove extension
    try pool.execute("DROP EXTENSION IF EXISTS pg_trgm;");
    defer {
        // Cleanup: restore extension
        pool.execute("CREATE EXTENSION IF NOT EXISTS pg_trgm;") catch |err| {
            std.debug.print("WARN: Could not restore pg_trgm: {}\n", .{err});
        };
    }
    
    // Act + Assert
    // ...
}
```
