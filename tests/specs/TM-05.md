# Test Spec: TM-05 - Reactivate tenant

**Requirement:** TM-05 - Reactivate tenant
**Priority:** MUST
**Test layer:** integration, e2e

## Test Cases

### TC-TM-05-01: Reactivate persists ACTIVE status
**Given:** An authenticated PLATFORM_ADMIN and a tenant currently INACTIVE.
**When:** The admin confirms tenant reactivation.
**Then:** The API returns HTTP 200 with status ACTIVE and the persisted tenant status is ACTIVE.
**Layer:** integration
**Acceptance criterion mapped:** TM-05 AC1
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-05-01)

### TC-TM-05-02: Reactivate is idempotent for ACTIVE tenant
**Given:** A tenant already in ACTIVE status.
**When:** Reactivate is requested again.
**Then:** The API returns HTTP 200 and the same ACTIVE state without side effects.
**Layer:** integration
**Acceptance criterion mapped:** TM-05 AC3
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-05-02)

### TC-TM-05-03: Non-admin cannot reactivate
**Given:** A caller with a non-PLATFORM_ADMIN role.
**When:** Reactivate is requested for an INACTIVE tenant.
**Then:** The API denies the action with HTTP 403 authorization failure.
**Layer:** integration
**Acceptance criterion mapped:** TM-05 AC4
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-05-03)

### TC-TM-UI-08: UI lifecycle transition back to ACTIVE
**Given:** A tenant row shown as Inactive in tenant management.
**When:** PLATFORM_ADMIN confirms Reactivate.
**Then:** The screen shows status Active and only Deactivate control for that row.
**Layer:** e2e
**Acceptance criterion mapped:** TM-05 AC1 and AC3; UI state transition coverage
**Implemented in:** web/tests/e2e/tenants.e2e.spec.ts (TC-TM-UI-08)

### TC-TM-UI-09: UI controls switch from Reactivate to Deactivate after activation
**Given:** A tenant row transitions from INACTIVE to ACTIVE during the test.
**When:** Reactivate is confirmed.
**Then:** Reactivate control disappears and Deactivate control is shown.
**Layer:** e2e
**Acceptance criterion mapped:** TM-05 AC1 and AC3; UI state transition coverage
**Implemented in:** web/tests/e2e/tenants.e2e.spec.ts (TC-TM-UI-09)

## Notes

- Integration tests are self-sufficient: they require BPM_TEST_DB_URL and fail clearly via SkipZigTest only when the env var is absent.
- Fixture isolation uses per-test tenant slugs with deterministic cleanup.
- TM-05 AC2 (normal operations resume after reactivation) is covered by cross-cutting tenant-activity policy suites; TM-05-focused tests here validate reactivation behavior, idempotency, authorization, and UI state transitions.
