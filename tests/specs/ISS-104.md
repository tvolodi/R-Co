## Test Cases

### TC-ISS-104-INT-01: Migration adds nullable artifact_hash column

**Given:**
- The integration database is initialized and migration 084_iss104_artifact_hash.sql has been applied.

**When:**
- The schema metadata for `instances.artifact_hash` is queried from `information_schema.columns`.

**Then:**
- Column exists with `data_type = 'text'` and `is_nullable = 'YES'`.
- Existing rows (if any) have `artifact_hash IS NULL`.

**Requirement mapped:** ISS-104 Acceptance Criterion 1  
**Layer:** integration  
**Deterministic:** Yes — schema snapshot is consistent within a test DB session.

---

### TC-ISS-104-INT-02: Repo-backed instance persists artifact hash

**Given:**
- An active definition exists in `process_definitions` table.
- The definition has a non-NULL `definition_artifact_hash` value (e.g., `"0123456789abcdef..."`).

**When:**
- An instance is started from that definition via `InstanceStore.create()`.
- The instance creation transaction completes.

**Then:**
- The instance row has `artifact_hash = definition_artifact_hash` (matches the definition's hash).
- The instance can be queried with `SELECT artifact_hash FROM instances WHERE instance_id = $1`.
- The hash is immutable (any subsequent read returns the same value).

**Requirement mapped:** ISS-104 Acceptance Criterion 2  
**Layer:** integration  
**Deterministic:** Yes — per-test UUID fixtures isolate rows.

---

### TC-ISS-104-INT-03: Non-repo instance has NULL artifact_hash

**Given:**
- An active definition exists with `definition_artifact_hash = NULL` (non-repository-backed).

**When:**
- An instance is started from that definition via `InstanceStore.create()`.

**Then:**
- The instance row has `artifact_hash IS NULL`.
- No error is raised; instance start succeeds normally.

**Requirement mapped:** Backward compatibility (graceful fallback for non-repo definitions)  
**Layer:** integration  
**Deterministic:** Yes — per-test UUID fixtures isolate rows.

---

### TC-ISS-104-INT-04: Reproducibility query resolves instance to artifact

**Given:**
- An instance was created from a repo-backed definition with a known artifact hash `"abc123..."`.
- The instance_id is known.

**When:**
- A reproducibility query is executed:
  ```sql
  SELECT artifact_hash FROM instances WHERE instance_id = $1
  ```

**Then:**
- The query returns `artifact_hash = "abc123..."`.
- The hash can be used to look up the definition in the artifacts registry (not tested here, but pattern is documented).

**Requirement mapped:** ISS-104 Acceptance Criterion 3  
**Layer:** integration  
**Deterministic:** Yes — direct DB query validates immutable metadata.
