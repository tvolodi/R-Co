# Test Spec: PD-04 — Definition lifecycle

**Requirement:** PD-04 — Definition lifecycle (MUST) — A process definition SHALL progress
through a defined sequence of statuses: DRAFT → ACTIVE → DEPRECATED → ARCHIVED. Transitions
outside this sequence SHALL be rejected with an error. The ARCHIVED status is terminal.

**Priority:** MUST  
**Test layer:** integration (Store.deprecate() and Store.archive() require a real PostgreSQL database)

---

## Shared preconditions

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()`).
- A `definition.Store` is created with a live `Pool`.
- A fixed `created_by` UUID `00000000-0000-0000-0000-000000000099` is used in all tests.
- Each test that writes to the database removes its rows on exit via `cleanupByName()`.
- A minimal valid graph (START → USER_TASK → END) is reused across tests.
- State is built by chaining store operations:
  - DEPRECATED definition: `create` → `activate` → `deprecate`
  - ARCHIVED definition: `create` → `activate` → `deprecate` → `archive`

---

## Test Cases

### TC-PD-04-01: DRAFT → ACTIVE via activate() — reference only

**Given:** a DRAFT definition.  
**When:** `Store.activate(id)` is called.  
**Then:** the definition transitions to ACTIVE.

**Layer:** integration  
**Coverage note:** This transition is fully covered by TC-PD-03-03 and TC-PD-03-01. No
duplicate test is written here. This entry exists for traceability to PD-04 requirement §DRAFT→ACTIVE.

**Status:** COVERED BY TC-PD-03-03 (reference only; not re-tested in pd04_lifecycle_test.zig)

---

### TC-PD-04-02: ACTIVE → DEPRECATED via deprecate() — success

**Given:** a definition in status ACTIVE.  
**When:** `Store.deprecate(id)` is called.  
**Then:**
- Returns success (no error).
- The returned `Definition` has `status = DEPRECATED`.
- `Store.getById(id)` also shows `status = DEPRECATED`.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "GIVEN a definition in ACTIVE status, WHEN
`deprecate()` is called, THEN status changes to DEPRECATED."

---

### TC-PD-04-03: DEPRECATED → ARCHIVED via archive() — success; archived_at is set

**Given:** a definition in status DEPRECATED (reached via create → activate → deprecate).  
**When:** `Store.archive(id)` is called.  
**Then:**
- Returns success (no error).
- The returned `Definition` has `status = ARCHIVED`.
- The returned `Definition` has `archived_at != null` (timestamp is non-null after archive).
- `Store.getById(id)` also shows `status = ARCHIVED` and `archived_at != null`.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "GIVEN a DEPRECATED definition, WHEN `archive()` is
called, THEN status changes to ARCHIVED and `archived_at` is set to the current timestamp."

---

### TC-PD-04-04: Forbidden: deprecate() on DRAFT → InvalidStatusTransition

**Given:** a definition in status DRAFT (newly created, never activated).  
**When:** `Store.deprecate(id)` is called.  
**Then:** returns `DefinitionError.InvalidStatusTransition`.  
**Rationale:** Only ACTIVE definitions may be deprecated.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "Transitions that skip a step (e.g. DRAFT → DEPRECATED)
SHALL be rejected with InvalidStatusTransition."

---

### TC-PD-04-05: Forbidden: archive() on DRAFT → InvalidStatusTransition

**Given:** a definition in status DRAFT (newly created, never activated).  
**When:** `Store.archive(id)` is called.  
**Then:** returns `DefinitionError.InvalidStatusTransition`.  
**Rationale:** Only DEPRECATED definitions may be archived.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "Transitions that skip a step (e.g. DRAFT → ARCHIVED)
SHALL be rejected with InvalidStatusTransition."

---

### TC-PD-04-06: Forbidden: archive() on ACTIVE → InvalidStatusTransition

**Given:** a definition in status ACTIVE (reached via create → activate).  
**When:** `Store.archive(id)` is called.  
**Then:** returns `DefinitionError.InvalidStatusTransition`.  
**Rationale:** ACTIVE definitions must be deprecated before they can be archived.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "archive() is only permitted from DEPRECATED status;
calling it on ACTIVE SHALL be rejected."

---

### TC-PD-04-07: Forbidden: deprecate() on ARCHIVED → InvalidStatusTransition

**Given:** a definition in status ARCHIVED (reached via create → activate → deprecate → archive).  
**When:** `Store.deprecate(id)` is called.  
**Then:** returns `DefinitionError.InvalidStatusTransition`.  
**Rationale:** ARCHIVED is a terminal status; no further lifecycle transitions are permitted.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "ARCHIVED is a terminal status. Any further status
transition SHALL be rejected with InvalidStatusTransition."

---

### TC-PD-04-08: Forbidden: archive() on ARCHIVED → InvalidStatusTransition

**Given:** a definition in status ARCHIVED (reached via create → activate → deprecate → archive).  
**When:** `Store.archive(id)` is called again.  
**Then:** returns `DefinitionError.InvalidStatusTransition`.  
**Rationale:** ARCHIVED is a terminal status; re-archiving is not permitted.

**Layer:** integration  
**Acceptance criterion mapped:** PD-04 — "ARCHIVED is a terminal status. Any further status
transition SHALL be rejected with InvalidStatusTransition."
