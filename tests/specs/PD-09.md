# Test Spec: PD-09 — Definition import/export

**Requirement:** PD-09 — Definition import/export (SHOULD) — The platform SHALL support export of
a definition as a self-contained JSON document and import from the same format, enabling migration
between environments.

**Priority:** SHOULD
**Test layer:** unit (EXPORT_SCHEMA_VERSION constant check; all Store paths require DB and are
stubbed), integration (`ExportImportStore.exportDefinition()`, `ExportImportStore.importDefinition()`)

---

## Shared preconditions

### Unit tests (`tests/unit/test_export_import.zig`)

- One pure test is executable without a database:
  - `TC-PD-09-const`: checks at compile-time that `EXPORT_SCHEMA_VERSION == "bpm/definition/v1"`.
- All `ExportImportStore` methods (`exportDefinition`, `importDefinition`) require a live database
  connection through `Pool.acquire()`.  All DB-dependent test blocks return `error.SkipZigTest`
  and are catalogued for requirement traceability only.
- Full verification is provided by the integration layer below.

### Integration tests (`tests/integration/test_export_import_integration.zig`)

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()` at the start of each test).
- A `bpm.pool.Pool` is created per test with `pool_size = 5`.
- An `ExportImportStore` is constructed as `ExportImportStore{ .pool = &pool }`.
- Definitions are inserted via `bpm.definition.Store.create()` using test names prefixed with
  `"TC-PD-09-"` so cleanup via `cleanupByName()` covers all test rows.
- The unknown-definition UUID used for negative tests is
  `"ffffffff-ffff-ffff-ffff-ffffffffffff"`.
- `std.testing.allocator` is used throughout; all `ExportDocument` values returned by
  `exportDefinition()` are freed with `freeExportDocument()`; all `Definition` values are freed
  with `freeDefinition()`.

### TC-PD-09-const: EXPORT_SCHEMA_VERSION equals "bpm/definition/v1"

**Given:** The `export_import` module is compiled.
**When:** `EXPORT_SCHEMA_VERSION` is read at compile time.
**Then:** Its value equals `"bpm/definition/v1"`.
**Layer:** unit (comptime check + runtime `expectEqualStrings`)
**DB required:** No
**Acceptance criterion mapped:** PD-09 — "the platform returns a self-contained JSON document
containing … a `bpm_export_schema_version` field."

---

### TC-PD-09-01: Export happy path — any status

**Given:** A definition exists in `process_definitions` with status ACTIVE (or any other status).
It has a known `name`, `version`, `description`, and `graph`.
**When:** `ExportImportStore.exportDefinition(allocator, definition_id)` is called.
**Then:**
- Returns `ExportDocument` without error.
- `doc.bpm_export_schema_version` equals `"bpm/definition/v1"`.
- `doc.name` equals the definition's `name`.
- `doc.version` equals the definition's `version`.
- `doc.graph.nodes.len` equals the definition graph's node count.
- `doc.exported_at` is a non-empty string.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — "GIVEN a definition with any status, WHEN exported, THEN
the platform returns a self-contained JSON document containing all definition fields, the full
graph, and a `bpm_export_schema_version` field."

---

### TC-PD-09-02: Export unknown id returns `DefinitionNotFound`

**Given:** A UUID `U` does not exist in `process_definitions`.
**When:** `ExportImportStore.exportDefinition(allocator, U)` is called.
**Then:** Returns `ExportImportError.DefinitionNotFound`.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — export of a non-existent definition is rejected (maps to
HTTP 404).

---

### TC-PD-09-03: Import happy path — creates with DRAFT status

**Given:** A valid `ExportDocument` with `bpm_export_schema_version = "bpm/definition/v1"`, a
name+version combination not present in `process_definitions`, and a structurally and
semantically valid graph.
**When:** `ExportImportStore.importDefinition(allocator, doc)` is called.
**Then:**
- Returns `Definition` without error.
- `def.status` equals `DRAFT`.
- `def.name` equals `doc.name`.
- `def.version` equals `doc.version`.
- `def.id` is not the all-zeros UUID (a new platform-assigned UUID was assigned).
- A row now exists in `process_definitions` for the returned `def.id`.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — "GIVEN a valid exported JSON document, WHEN imported to
a target environment with no conflicting name+version, THEN the definition is created with
`status = DRAFT` on the target."

---

### TC-PD-09-04: Import with name+version conflict returns `NameVersionConflict`

**Given:** A definition with name `N` and version `V` already exists in `process_definitions`.
**When:** `ExportImportStore.importDefinition(allocator, doc)` is called with `doc.name = N` and
`doc.version = V`.
**Then:**
- Returns `ExportImportError.NameVersionConflict`.
- No new row is inserted into `process_definitions`.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — "GIVEN an exported document where the same name+version
already exists on the target, WHEN imported, THEN the import is rejected with HTTP 409."

---

### TC-PD-09-05: Import with invalid CEL condition returns `InvalidGraph`

**Given:** An `ExportDocument` with `bpm_export_schema_version = "bpm/definition/v1"` whose graph
contains an `EXCLUSIVE_GATEWAY` with a non-default outgoing edge carrying a syntactically invalid
CEL condition (e.g. `"((unclosed"`).
**When:** `ExportImportStore.importDefinition(allocator, doc)` is called.
**Then:**
- Returns `ExportImportError.InvalidGraph`.
- No new row is inserted into `process_definitions`.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — "CEL conditions on imported definitions are re-validated
by the target platform's CEL interpreter; invalid expressions cause import to be rejected with
HTTP 422."

---

### TC-PD-09-06: Import with unknown schema version returns `UnknownSchemaVersion`

**Given:** An `ExportDocument` with `bpm_export_schema_version = "bpm/definition/v99"`.
**When:** `ExportImportStore.importDefinition(allocator, doc)` is called.
**Then:** Returns `ExportImportError.UnknownSchemaVersion`.
**Layer:** integration (also exercisable without DB since the check is the first step)
**Acceptance criterion mapped:** PD-09 — unknown schema version is rejected before any DB access.

---

### TC-PD-09-07: Export-import round-trip preserves full graph

**Given:** A definition with a graph containing nodes of various types:
- A `START` node
- A `HUMAN_TASK` node with a `role` attribute
- An `EXCLUSIVE_GATEWAY` node
- Two `END` nodes
- A non-default outgoing edge from the gateway carrying a CEL `condition` expression
  (`"approved == true"`)
- A default outgoing edge from the gateway with `is_default = true` and no condition

**When:**
1. `ExportImportStore.exportDefinition()` is called to produce `doc_original`.
2. A modified copy `import_doc` is made with a different `name` to avoid name+version conflict.
3. `ExportImportStore.importDefinition(import_doc)` is called to produce `imported_def`.
4. `ExportImportStore.exportDefinition(imported_def.id)` is called to produce `doc_imported`.

**Then:**
- `doc_imported.graph.nodes.len` equals `doc_original.graph.nodes.len`.
- Node types in `doc_imported.graph` match those in `doc_original.graph` (same order).
- The edge with `is_default = true` in `doc_original` retains `is_default = true` in `doc_imported`.
- The edge with `condition = "approved == true"` in `doc_original` retains that condition
  in `doc_imported`.
**Layer:** integration
**Acceptance criterion mapped:** PD-09 — all definition fields (including full graph with nodes,
edges, conditions, and `is_default` flags) are preserved through export → import.

## Edge Cases

- **Exporting a DRAFT definition:** Permitted; TC-PD-09-01 can be extended to cover DRAFT status.
  The export function works for any status (DRAFT, ACTIVE, DEPRECATED, ARCHIVED).

- **Import with empty description:** Handled naturally; `importDefinition` passes `null` to
  `Store.create()` when `doc.description.len == 0`.

- **Pool exhausted during export or import:** `ExportImportStore` returns `ExportImportError.PoolExhausted`
  when `Pool.acquire()` fails with `ExhaustedPool`.  This path is catalogued in the DB-02 pool test
  suite (DB-02 tests cover `ExhaustedPool` propagation).

- **Import doc id field:** `doc.id` is informational only — not used during import.  The platform
  assigns a new UUID via `Store.create()`.  TC-PD-09-03 verifies the returned `def.id` is
  non-zero (a real new UUID was assigned).
