# Test Spec: SH-05 & SH-06 — Global Error Boundary & API Connectivity Banner

**Requirements:**
- SH-05 — An unhandled runtime error in any view SHALL be caught and render a recoverable error panel with a "reload this view" action, without crashing the entire application.
- SH-06 — If `GET /health/ready` returns non-200, the shell SHALL display a non-blocking banner: "Platform is currently unavailable — some actions may fail." The banner auto-dismisses when health recovers.

**Priority:** SH-05 = MUST · SH-06 = SHOULD
**Run:** WF02-shf1b-20260528
**Test layer:** unit (SH-05), e2e (SH-06)

---

## SH-05 Test Cases

### TC-SH05-01: Child component throws → fallback panel shown
**Given:** An `<ErrorBoundary>` wrapping a child component  
**When:** The child throws during render  
**Then:** `data-testid="error-boundary-panel"` is visible in the DOM; the child content is not rendered  
**Layer:** unit (Vitest + React Testing Library)  
**Acceptance criterion mapped:** error boundary catches render error and shows panel (SH-05 MUST)

---

### TC-SH05-02: "Try again" resets state — panel gone, content visible
**Given:** A `ToggleThrowWrapper` wrapping an `<ErrorBoundary>` where the throw flag is set (panel showing)  
**When:** The throw flag is cleared and then `data-testid="error-boundary-reset"` is clicked  
**Then:** The fallback panel is removed from the DOM; `data-testid="normal-content"` is visible  
**Layer:** unit (Vitest + React Testing Library)  
**Acceptance criterion mapped:** recoverable error panel with "reload this view" action (SH-05 MUST)

---

### TC-SH05-02b: No error → normal content visible without any panel
**Given:** An `<ErrorBoundary>` wrapping a child that does not throw  
**When:** The component mounts  
**Then:** `data-testid="normal-content"` is visible; `data-testid="error-boundary-panel"` is not in the DOM  
**Layer:** unit (Vitest + React Testing Library)  
**Acceptance criterion mapped:** boundary renders children when no error exists (SH-05 MUST)

---

### TC-SH05-03: After reset, a new error in the same child shows the fallback again
**Given:** An `<ErrorBoundary>` whose state was just reset (normal content visible)  
**When:** The child throws again  
**Then:** `data-testid="error-boundary-panel"` is visible; the normal content is hidden  
**Layer:** unit (Vitest + React Testing Library)  
**Acceptance criterion mapped:** error boundary remains functional after recovery (SH-05 MUST)

---

## SH-06 Test Cases

### TC-SH06-01: /health/ready returns 200 → banner NOT visible
**Given:** `GET /health/ready` is stubbed to return HTTP 200  
**When:** The app shell mounts and the hook performs its immediate check  
**Then:** No element with `data-testid="connectivity-banner"` is present in the DOM  
**Layer:** e2e (Playwright)  
**Acceptance criterion mapped:** banner does not appear when backend is healthy (SH-06 SHOULD)

---

### TC-SH06-02: /health/ready returns 503 → banner visible
**Given:** `GET /health/ready` is stubbed to return HTTP 503  
**When:** The app shell mounts and the hook performs its immediate check  
**Then:** `data-testid="connectivity-banner"` is visible; banner text contains "Platform is currently unavailable"  
**Layer:** e2e (Playwright)  
**Acceptance criterion mapped:** banner displays when backend is unhealthy (SH-06 SHOULD)

---

### TC-SH06-03: Banner disappears when health recovers
**Given:** `GET /health/ready` initially returns 503 (banner visible), then transitions to returning 200  
**When:** The next poll cycle fires and returns 200  
**Then:** `data-testid="connectivity-banner"` is no longer present in the DOM  
**Layer:** e2e (Playwright)  
**Acceptance criterion mapped:** banner auto-dismisses when health recovers (SH-06 SHOULD)
