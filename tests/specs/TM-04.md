# Test Spec: TM-04 - Deactivate tenant

**Requirement:** TM-04 - Deactivate tenant
**Priority:** MUST
**Test layer:** integration, e2e

## Test Cases

### TC-TM-04-01: Deactivate persists INACTIVE status
**Given:** An authenticated PLATFORM_ADMIN and an ACTIVE tenant fixture.
**When:** The admin confirms tenant deactivation.
**Then:** The API returns HTTP 200 with status INACTIVE and the persisted tenant status is INACTIVE.
**Layer:** integration
**Acceptance criterion mapped:** TM-04 AC1
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-04-01)

### TC-TM-04-02: Deactivate is idempotent for INACTIVE tenant
**Given:** A tenant already deactivated to INACTIVE.
**When:** Deactivate is requested again.
**Then:** The API returns HTTP 200 and the same INACTIVE state without side effects.
**Layer:** integration
**Acceptance criterion mapped:** TM-04 AC3
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-04-02)

### TC-TM-04-04: Non-admin cannot deactivate
**Given:** A caller with a non-PLATFORM_ADMIN role.
**When:** Deactivate is requested for a tenant.
**Then:** The API denies the action with HTTP 403 authorization failure.
**Layer:** integration
**Acceptance criterion mapped:** TM-04 AC4
**Implemented in:** tests/integration/tm01_tenant_list_test.zig (TC-TM-04-04)

### TC-TM-UI-08: UI lifecycle transition to INACTIVE and back to ACTIVE
**Given:** A PLATFORM_ADMIN on tenant management with lifecycle controls.
**When:** The admin confirms Deactivate for an ACTIVE tenant.
**Then:** The screen shows status Inactive and only Reactivate control for that row.
**Layer:** e2e
**Acceptance criterion mapped:** TM-04 AC1; UI state transition coverage
**Implemented in:** web/tests/e2e/tenants.e2e.spec.ts (TC-TM-UI-08)

### TC-TM-UI-09: UI control state follows tenant status
**Given:** A tenant row in ACTIVE or INACTIVE state.
**When:** Lifecycle actions are confirmed from the row.
**Then:** ACTIVE shows Deactivate only; INACTIVE shows Reactivate only.
**Layer:** e2e
**Acceptance criterion mapped:** TM-04 AC1 and AC3; UI state transition coverage
**Implemented in:** web/tests/e2e/tenants.e2e.spec.ts (TC-TM-UI-09)

## Notes

- Integration tests are self-sufficient: they require BPM_TEST_DB_URL and fail clearly via SkipZigTest only when the env var is absent.
- Fixture isolation uses per-test tenant slugs with cleanup before/after each test block.
- TM-04 AC2 (inactive tenant blocked for normal operations) is covered by policy-level requirements/tests under ADP-03 and OIDC/API authorization suites; TM-04-focused tests here validate lifecycle API behavior and authorization boundaries for deactivate itself.
