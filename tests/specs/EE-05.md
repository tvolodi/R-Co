# Test Spec: EE-05 — Exclusive gateway

**Requirement:** EE-05 — When the execution token reaches an EXCLUSIVE_GATEWAY, the platform SHALL evaluate outgoing edge CEL conditions in declared order and follow the first edge whose condition evaluates to `true`. One edge MAY be designated as the default edge via a boolean `is_default` flag. The default edge is evaluated last, regardless of declared order, and does not carry a condition expression. If no condition matches and no default edge is defined, the engine transitions the instance to ERROR status per EE-10.  
**Priority:** MUST  
**Test layer:** unit

## Detailed Test Cases

### TC-EE-05-01: EXCLUSIVE_GATEWAY follows first matching condition

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`high_value`) and EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`low_value`).
- Edge `e1` (source=`gw`, target=`high_value`, is_default=false, condition=`variables.amount > 1000`) declared first.
- Edge `e2` (source=`gw`, target=`low_value`, is_default=false, condition=`variables.status == "approved"`) declared second.
- An `InstanceState` with one token on `gw` and `variables = { "amount": 1500, "status": "pending" }`.

**When:**
- `processNodeEntry` (via `transition()`) evaluates the gateway.

**Then:**
- The token moves to `high_value`.
- `pending_task_nodes` contains `"high_value"`.
- `pending_task_nodes` does NOT contain `"low_value"`.
- Exactly one outgoing edge was followed.

**Layer:** unit  
**Acceptance criterion mapped:** AC1 — token follows first edge whose condition evaluates to `true` against current instance variables; AC5 — exactly one edge followed.

### TC-EE-05-02: EXCLUSIVE_GATEWAY respects declared order — second condition wins when first is false

**Given:**
- Same graph as TC-EE-05-01.
- `InstanceState` with token on `gw`, `variables = { "amount": 500, "status": "approved" }`.

**When:**
- `transition()` evaluates the gateway.

**Then:**
- Condition on `e1` (`variables.amount > 1000`) evaluates to `false`.
- Condition on `e2` (`variables.status == "approved"`) evaluates to `true`.
- Token moves to `low_value`.
- `pending_task_nodes` = `["low_value"]`.

**Layer:** unit  
**Acceptance criterion mapped:** AC1 — conditions evaluated in declared order; first true wins.

---

### TC-EE-05-03: EXCLUSIVE_GATEWAY with only a default edge always follows it

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`next`).
- Edge `e_default` (source=`gw`, target=`next`, is_default=true, condition=null).
- No non-default edges.
- `InstanceState` with token on `gw`, `variables = {}`.

**When:**
- `transition()` evaluates the gateway.

**Then:**
- Token moves to `next`.
- `pending_task_nodes` = `["next"]`.

**Layer:** unit  
**Acceptance criterion mapped:** AC2 — default edge followed when it is the only edge.

---

### TC-EE-05-04: Non-default conditions all false — default edge is followed

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`branch_a`) and EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`default_branch`).
- Edge `e1` (source=`gw`, target=`branch_a`, is_default=false, condition=`variables.amount > 1000`).
- Edge `e_default` (source=`gw`, target=`default_branch`, is_default=true, condition=null).
- `InstanceState` with token on `gw`, `variables = { "amount": 0 }`.

**When:**
- `transition()` evaluates the gateway.

**Then:**
- `variables.amount > 1000` is `false`.
- Token moves to `default_branch`.
- `pending_task_nodes` = `["default_branch"]`.

**Layer:** unit  
**Acceptance criterion mapped:** AC2 — default edge is evaluated last and followed when no non-default condition matches.

---

### TC-EE-05-05: CEL undefined variable treated as false — iteration continues to default

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`target`).
- Edge `e1` (source=`gw`, target=HUMAN_TASK(`unreachable`), is_default=false, condition=`variables.missing_key`).
- Edge `e_default` (source=`gw`, target=`target`, is_default=true, condition=null).
- `InstanceState` with token on `gw`, `variables = {}` (key `missing_key` absent).

**When:**
- `transition()` evaluates the gateway.

**Then:**
- `cel.evaluate` returns `CelError.EvalError` for `variables.missing_key` (key absent).
- The error is caught and treated as `false` (condition does not match).
- No error is propagated; iteration continues to the default edge.
- Token moves to `target`.
- `pending_task_nodes` = `["target"]`.

**Layer:** unit  
**Acceptance criterion mapped:** AC4 — a CEL runtime error MUST be treated as `false` for that condition; edge-case note — undefined variable → CEL runtime error → treated as false.

---

### TC-EE-05-06: CEL type mismatch treated as false — iteration continues to default

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`target`).
- Edge `e1` (source=`gw`, target=HUMAN_TASK(`unreachable`), is_default=false, condition=`variables.x > "not a number"`).
- Edge `e_default` (source=`gw`, target=`target`, is_default=true, condition=null).
- `InstanceState` with token on `gw`, `variables = { "x": 5 }`.

**When:**
- `transition()` evaluates the gateway.

**Then:**
- `cel.evaluate` returns `CelError.EvalError` (numeric `>` string is a type mismatch).
- The error is treated as `false`; iteration continues.
- Token moves to `target`.
- `pending_task_nodes` = `["target"]`.

**Layer:** unit  
**Acceptance criterion mapped:** AC4 — CEL type mismatch MUST be treated as `false`.

---

### TC-EE-05-07: No matching condition and no default edge → TransitionError.NoMatchingEdge

**Given:**
- A `DefinitionGraph` with nodes: START → EXCLUSIVE_GATEWAY(`gw`) → HUMAN_TASK(`branch_a`).
- Edge `e1` (source=`gw`, target=`branch_a`, is_default=false, condition=`variables.amount > 1000`).
- No default edge on `gw`.
- `InstanceState` with token on `gw`, `variables = { "amount": 0 }`.

**When:**
- `transition()` evaluates the gateway.

**Then:**
- `variables.amount > 1000` evaluates to `false`.
- No default edge exists.
- `transition()` returns `TransitionError.NoMatchingEdge`.
- The calling layer transitions the instance to ERROR status per EE-10.

**Layer:** unit  
**Acceptance criterion mapped:** AC3 — GIVEN no condition evaluates to `true` and no default edge exists, THEN the instance transitions to ERROR.

### TC-EE-05-15: CEL evaluator — missing variable key → CelError.EvalError

**Given:** Variables map is empty (key `"missing"` absent).  
**When:** `cel.evaluate(allocator, "variables.missing", vars)` is called.  
**Then:** Returns `error.EvalError`.  
**Layer:** unit (cel)  
**Acceptance criterion mapped:** AC4 — accessing an undefined variable triggers a CEL runtime error; this is the root cause of the "treated as false" gateway behaviour in TC-EE-05-05.

---

### TC-EE-05-16: CEL evaluator — type mismatch in comparison → CelError.EvalError

**Given:** Variables map contains `"x" → 5` (integer).  
**When:** `cel.evaluate(allocator, "variables.x > \"not a number\"", vars)` is called.  
**Then:** Returns `error.EvalError` (numeric `>` string operand is a type mismatch in `applyCmp`).  
**Layer:** unit (cel)  
**Acceptance criterion mapped:** AC4 — a CEL runtime type error is surfaced as `EvalError` and must be treated as `false` by the gateway.

---

### TC-EE-05-17: CEL evaluator — malformed expression → CelError.ParseError

**Given:** Variables map is empty.  
**When:** `cel.evaluate(allocator, "> >", vars)` is called.  
**Then:** Returns `error.ParseError`.  
**Layer:** unit (cel)  
**Acceptance criterion mapped:** AC4 / CEL evaluator — syntactically invalid expressions are rejected at parse time with `ParseError`; they cannot silently evaluate to any value.
