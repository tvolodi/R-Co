# Test Spec: EE-07 — Parallel Gateway (join)

**Requirement:** EE-07 — A PARALLEL_GATEWAY acting as join SHALL wait until all **active** incoming tokens have arrived before activating the single outgoing edge. An incoming branch that was cancelled (via EE-08) contributes no token and is excluded from the join count. If all branches of a parallel split are cancelled before any reaches the join, the join node is also cancelled and the instance transitions to CANCELLED status.  
**Priority:** MUST  
**Test layer:** unit (AC1–AC5), integration (DB-03 exactly-once guarantee)

---

## Acceptance Criteria

| ID | Criterion |
|---|---|
| AC1 | GIVEN N active tokens approaching a PARALLEL_GATEWAY join, WHEN all N active tokens have arrived, THEN the join fires and a single outgoing token is created. |
| AC2 | "Active" excludes tokens on branches cancelled via EE-08. |
| AC3 | GIVEN one branch is cancelled and all remaining active branches arrive at the join, WHEN the last active token arrives, THEN the join fires normally (cancelled branch excluded from count). |
| AC4 | GIVEN all branches of a split are cancelled before any reaches the join, WHEN the last cancellation occurs, THEN the join node is also cancelled and the instance transitions to CANCELLED status. |
| AC5 | The join fires exactly once regardless of the arrival order of concurrent tokens. |

## Detailed Test Cases

### EE-07-TC-01: Normal 2-branch join — both tokens arrive → join fires, 1 outgoing token

**Source:** `src/engine/transition.zig` — `"TC-EE-07-04: PARALLEL_JOIN event records branch_id with edge_index 0 as outgoing_token_id"`

**Given:**
- A `DefinitionGraph` with nodes: `HUMAN_TASK("t1")`, `HUMAN_TASK("t2")`, `PARALLEL_GATEWAY("join_gw")`, `HUMAN_TASK("t3")`.
- Edges: `e1` (t1 → join_gw), `e2` (t2 → join_gw), `e3` (join_gw → t3).
- An `InstanceState` with **two** tokens both parked on `"join_gw"`:
  - token A: `branch_id = "<hex>/split_gw/1"` (arrived first — stored first in tokens slice)
  - token B: `branch_id = "<hex>/split_gw/0"` (arrived second)
- `cancelled_branch_ids = []`.

**When:**
- `processNodeEntry(allocator, graph, state, "join_gw")` is called.

**Then:**
- `result.tokens.len == 1` — one merged token on the outgoing node "t3".
- `result.tokens[0].node_id == "t3"`.
- `result.tokens[0].branch_id == "<hex>/split_gw/0"` — the deterministic merged branch_id uses edge_index "0".
- `result.pending_events.len == 1`.
- `result.pending_events[0]` has active tag `.parallel_join`.
- `join_payload.join_node_id == "join_gw"`.
- `join_payload.branch_ids_arrived.len == 2`.
- `join_payload.branch_ids_cancelled.len == 0`.
- `join_payload.outgoing_token_id == "<hex>/split_gw/0"`.

**Layer:** unit  
**Acceptance criteria mapped:** AC1 — all N active tokens arrived, join fires, 1 outgoing token created; AC5 — regardless of arrival order, merged branch_id is always the one with edge_index "0", confirming deterministic exactly-once behaviour.

### EE-07-TC-02: Cancelled-branch exclusion — 1 of 2 branches cancelled, remaining arrives → join fires

**Source:** `src/engine/transition.zig` — `"TC-EE-07-01: join waits when one branch cancelled, fires when remaining active branch arrives"`

**Given:**
- A `DefinitionGraph` with nodes: `PARALLEL_GATEWAY("split_gw")`, `HUMAN_TASK("t1")`, `HUMAN_TASK("t2")`, `PARALLEL_GATEWAY("join_gw")`, `HUMAN_TASK("t3")`.
- Edges: `e1` (split_gw → t1), `e2` (split_gw → t2), `e3` (t1 → join_gw), `e4` (t2 → join_gw), `e5` (join_gw → t3).
- An `InstanceState` with **one** token on `"join_gw"`:
  - token: `branch_id = "<hex>/split_gw/1"` (the remaining active branch, arrived).
- `cancelled_branch_ids = ["<hex>/split_gw/0"]` — branch 0 was cancelled by EE-08.

**When:**
- `processNodeEntry(allocator, graph, state, "join_gw")` is called.

**Then:**
- `expected_count = incoming_count(2) − cancelled_count(1) = 1`.
- `arrived_count = 1`.
- Join fires (1 == 1).
- `result.tokens.len == 1` — one merged token on "t3".
- `result.pending_events.len == 1` — one PARALLEL_JOIN event.
- `join_payload.branch_ids_arrived.len == 1` (only the active branch).
- `join_payload.branch_ids_cancelled.len == 1` (the cancelled branch is recorded).

**Layer:** unit  
**Acceptance criteria mapped:** AC2 — "active" excludes cancelled branches; AC3 — 1 cancelled branch, remaining active branch arrives → join fires normally.

### EE-07-TC-03: All branches cancelled → INSTANCE_CANCELLED event, instance CANCELLED status

**Source:** `src/engine/transition.zig` — `"TC-EE-07-03: all-branches-cancelled path → INSTANCE_CANCELLED event, status CANCELLED"`

**Given:**
- A `DefinitionGraph` with nodes: `HUMAN_TASK("t1")`, `HUMAN_TASK("t2")`, `PARALLEL_GATEWAY("join_gw")`, `HUMAN_TASK("t3")`.
- Edges: `e1` (t1 → join_gw), `e2` (t2 → join_gw), `e3` (join_gw → t3).
- An `InstanceState` with a stray token on `"join_gw"` (EE-08 trigger call):
  - token: `branch_id = "<hex>/split_gw/0"`.
- `cancelled_branch_ids = ["<hex>/split_gw/0", "<hex>/split_gw/1"]` — both branches cancelled.

**When:**
- `processNodeEntry(allocator, graph, state, "join_gw")` is called.

**Then:**
- `expected_count = incoming_count(2) − cancelled_count(2) = 0`.
- All-cancelled path (step f) is taken.
- `result.status == .CANCELLED`.
- `result.tokens.len == 0` — all tokens cleared; terminal state.
- `result.pending_events.len == 1` — one `INSTANCE_CANCELLED` event.
- `cancel_payload.reason == "ALL_BRANCHES_CANCELLED"`.
- `cancel_payload.join_node_id != null` and `cancel_payload.join_node_id.? == "join_gw"`.
- `cancel_payload.branch_ids_cancelled.len == 2`.
- No `PARALLEL_JOIN` event is emitted (join did not fire).

**Layer:** unit  
**Acceptance criteria mapped:** AC4 — all branches of a split cancelled before any token reaches the join → join is cancelled, instance transitions to CANCELLED, `INSTANCE_CANCELLED` event appended.

### EE-07-TC-04: Exactly-once join firing — concurrent arrivals serialised by DB-03

**Source (unit-level verification):** `src/engine/transition.zig` — `"TC-EE-07-04: PARALLEL_JOIN event records branch_id with edge_index 0 as outgoing_token_id"`

**Note:** Full exactly-once is enforced by the DB-03 `SELECT FOR UPDATE` lock on `instance_projections`. This test case verifies the unit-level side: when both tokens are present on the join node (simulating two serialised `applyTransition` calls per §3 of the design), `processNodeEntry` produces exactly 1 merged token and exactly 1 `PARALLEL_JOIN` event.

**Given:**
- (same setup as EE-07-TC-01 — both tokens already on join_gw).
- Branch 1 token is stored first (simulating it "arrived first"), branch 0 token stored second.

**When:**
- `processNodeEntry` is called once (simulating T2 in the DB-03 serialisation example from the design §3).

**Then:**
- `result.tokens.len == 1` — exactly one merged token.
- `result.pending_events.len == 1` — exactly one `PARALLEL_JOIN` event.
- No double-firing: exactly one join fires for this pair of branches.

**DB-03 integration layer:** Under concurrent real workload, `applyTransition` calls for the same instance are serialised by `SELECT FOR UPDATE`. T1 parks branch 1, commits. T2 reads the committed state (branch 1 already parked), adds branch 2, fires the join. Exactly-once is a DB-level invariant; this unit test verifies the pure function side.

**Layer:** unit (pure function); integration (DB-03 lock — see `tests/integration/`)  
**Acceptance criteria mapped:** AC5 — join fires exactly once regardless of concurrent arrival order.

### EE-07-TC-05: 3-branch join — all 3 active branches arrive → join fires once, 1 outgoing token

**Source:** `tests/unit/test_ee07_parallel_join.zig` — `"TC-EE-07-05: 3-branch join — all 3 active branches arrive via task_completed → join fires, 1 outgoing token"`

**Given:**
- A `DefinitionGraph` with nodes: `HUMAN_TASK("t1")`, `HUMAN_TASK("t2")`, `HUMAN_TASK("t3")`, `PARALLEL_GATEWAY("join_gw")`, `HUMAN_TASK("t4")`.
- Edges: `e1` (t1 → join_gw), `e2` (t2 → join_gw), `e3` (t3 → join_gw), `e4` (join_gw → t4).
  - `join_gw` has `incoming_count = 3`, so it is a join node.
- An `InstanceState` with three tokens, one on each task:
  - token 0: `{node_id = "t1", branch_id = "<hex>/split_gw/0"}`
  - token 1: `{node_id = "t2", branch_id = "<hex>/split_gw/1"}`
  - token 2: `{node_id = "t3", branch_id = "<hex>/split_gw/2"}`
- `cancelled_branch_ids = []`.

**When:**
- `transition(alloc, graph, state0, task_completed("t1", {}))` → state1 (wait: 1/3 arrived)
- `transition(alloc, graph, state1, task_completed("t2", {}))` → state2 (wait: 2/3 arrived)
- `transition(alloc, graph, state2, task_completed("t3", {}))` → state3 (fire: 3/3 arrived)

**Then:**
- state1: `tokens = [{join_gw, branch_0}, {t2, branch_1}, {t3, branch_2}]`, `pending_events = []`.
- state2: `tokens = [{join_gw, branch_0}, {join_gw, branch_1}, {t3, branch_2}]`, `pending_events = []`.
- state3: `tokens.len == 1`, `tokens[0].node_id == "t4"`.
- `state3.pending_events.len == 1` — exactly one `PARALLEL_JOIN` event.
- `join_payload.join_node_id == "join_gw"`.
- `join_payload.branch_ids_arrived.len == 3`.
- `join_payload.branch_ids_cancelled.len == 0`.
- `state3.tokens[0].branch_id == "<hex>/split_gw/0"` — merged branch_id is the one with edge_index "0".

**Layer:** unit  
**Acceptance criteria mapped:** AC1 — N active tokens (N=3) approaching a join, all N arrive → join fires, single outgoing token created.
