# Test Spec: EXP-401 - Compensation Handler and Error-Boundary Metadata

**Requirement:** EXP-401
**Priority:** MUST
**Test layer:** integration (real PostgreSQL)

## Scope

This spec verifies the implemented EXP-401 behavior in the definition validation path:
- Compensation handler metadata shape and reachability checks
- Error-boundary metadata shape and attachment checks
- Reverse-order requirement enforcement (`reverse_order = true`)
- Reversibility gating for nodes that declare compensation metadata

## Test Cases

### TC-EXP-401-01: Valid compensation and error-boundary metadata is accepted
**Given:** A valid graph where a reversible activity declares a compensation handler and a reachable error-boundary node.
**When:** `DefinitionStore.create()` is called.
**Then:** Definition creation succeeds and no compensation/boundary violations are recorded.
**Layer:** integration
**Acceptance criterion mapped:** compensation handler + error-boundary behavior accepted when valid.

### TC-EXP-401-02: Unknown compensation scope is rejected
**Given:** A graph where `compensation_handler.scope_id` references a non-existent node.
**When:** `DefinitionStore.create()` is called.
**Then:** Creation fails with `GraphValidationFailed` and includes violation code `COMPENSATION_HANDLER_SCOPE_UNKNOWN`.
**Layer:** integration
**Acceptance criterion mapped:** handler reachability/scope validation.

### TC-EXP-401-03: reverse_order=false is rejected
**Given:** A graph where `compensation_handler.reverse_order` is explicitly `false`.
**When:** `DefinitionStore.create()` is called.
**Then:** Creation fails with `GraphValidationFailed` and includes `COMPENSATION_HANDLER_NOT_REVERSED`.
**Layer:** integration
**Acceptance criterion mapped:** reverse-order compensation requirement.

### TC-EXP-401-04: Irreversible node with compensation metadata is rejected
**Given:** A graph where a node with compensation metadata is marked `reversible=false`.
**When:** `DefinitionStore.create()` is called.
**Then:** Creation fails with `GraphValidationFailed` and includes `NON_REVERSIBLE_ACTIVITY`.
**Layer:** integration
**Acceptance criterion mapped:** reversible activity requirement.

### TC-EXP-401-05: Error-boundary events are required
**Given:** A graph with `error_boundary` metadata where one event name is empty.
**When:** `DefinitionStore.create()` is called.
**Then:** Creation fails with `GraphValidationFailed` and includes `ERROR_BOUNDARY_EVENTS_MISSING`.
**Layer:** integration
**Acceptance criterion mapped:** error-boundary event configuration validation.
