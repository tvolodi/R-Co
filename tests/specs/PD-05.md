# Test Spec: PD-05 — Node types

**Requirement:** PD-05 — Node types (MUST) — The platform SHALL support node types START, END,
HUMAN_TASK, SERVICE_TASK, EXCLUSIVE_GATEWAY, PARALLEL_GATEWAY, and TIMER. Each type SHALL have
mandatory and optional attribute schema that is validated at definition-save time.

**Priority:** MUST
**Test layer:** unit (`validateNodeAttributes`), integration (`Store.create()`)

---

## Shared preconditions

### Unit tests (`tests/unit/graph_node_attributes_test.zig`)

- Tests call `graph.validateNodeAttributes(allocator, graph)` directly — no DB required.
- Each graph contains a START node, the node under test, and an END node, with correct edges,
  so that no structural violations from `validateGraph` can interfere.
- `std.testing.allocator` is used; all `ValidationResult` values are freed per memory contract:
  `for (result.violations) |v| alloc.free(v.message); alloc.free(result.violations);`

### Integration tests (`tests/integration/pd05_node_types_test.zig`)

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()`).
- A `definition.Store` is created with a live `Pool`.
- Fixed `created_by` UUID `00000000-0000-0000-0000-000000000099` is used in all tests.
- Each test that writes to the database removes its rows on exit via `cleanupByName()`.

## Test Cases

### TC-PD-05-01: HUMAN_TASK with role present and non-empty → saves

**Given:** a graph containing a HUMAN_TASK node with `attributes = {"role": "approver"}`.
**When:** `validateNodeAttributes()` is called (unit) / `store.create()` is called (integration).
**Then:** result is valid; no violations; definition is created with status DRAFT.
**Layer:** unit, integration
**Acceptance criterion mapped:** PD-05 — "GIVEN a node with type = HUMAN_TASK, WHEN the definition
is saved, THEN the node MUST have a role attribute (non-empty string)."

### TC-PD-05-19: Multiple attribute violations → all violations collected (no early exit)

**Given:** a graph containing a HUMAN_TASK node (role absent) AND a SERVICE_TASK node
  (endpoint absent; timeout_ms = 60000 is valid).
**When:** `validateNodeAttributes()` is called (unit) / `store.create()` is called (integration).
**Then:** result is invalid; both `HUMAN_TASK_MISSING_ROLE` and `SERVICE_TASK_MISSING_ENDPOINT`
  violation codes are present in the same result; the function does NOT exit after the first
  failure — all nodes are checked.
**Layer:** unit, integration
**Acceptance criterion mapped:** PD-05 — all violations are collected in a single response
(no early exit after first failure).
