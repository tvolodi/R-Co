# Test Spec: ISS-0063 — OIDC login redirect loop regression

**Issue:** ISS-0063 — OIDC login redirect loop caused by Keycloak authority port mismatch, callback state loss on reload, and tenant-config localhost fallback mismatch
**Priority:** MUST
**Test layer:** integration, e2e

## Scope

This regression suite is intentionally minimal and real-environment only. It validates the three diagnosed causes that kept the login flow looping after Keycloak redirected the browser back to the app:

1. The backend tenant-config response must expose the browser-visible localhost authority with the exposed Keycloak port.
2. The OIDC authorization redirect must use that authority so Keycloak keeps generating URLs on `:8081`.
3. The callback state must survive a callback-page reload so `signinRedirectCallback()` can finish instead of restarting login.

## Test Cases

### TC-ISS-0063-00: suite preflight fails fast when required backend/browser prerequisites are missing
**Given:** The suite is started without `BPM_TEST_DB_URL`, or the backend / Keycloak readiness endpoints are not reachable
**When:** The ISS-0063 E2E file begins execution
**Then:** The test fails with a clear prerequisite error naming the missing env var or unhealthy service, instead of skipping
**Layer:** e2e
**Acceptance criterion mapped:** Self-sufficient real-backend/browser startup and explicit failure behavior

### TC-ISS-0063-01: tenant-config returns the browser-visible localhost authority with port 8081
**Given:** A real backend with migrations applied and the login browser origin using `localhost`
**When:** The browser requests `GET /api/tenant-config?host=localhost`
**Then:** The response returns HTTP 200, `oidc_authority` starts with `http://localhost:8081/realms/`, `client_id` equals `bpm-platform-api`, and the authority does not fall back to `127.0.0.1`
**Layer:** integration / e2e
**Acceptance criterion mapped:** Tenant-config authority consistency for the browser-visible host

### TC-ISS-0063-02: login redirect targets Keycloak on the preserved authority and completes the real Keycloak return path
**Given:** The real login page is open in a browser and the backend tenant-config response is available
**When:** The user starts OIDC login and Keycloak returns the browser to the app through `/auth/callback`
**Then:** The captured authorization URL contains `localhost:8081`, contains the expected realm path, and the browser lands on the authenticated workspace after the Keycloak return completes
**Layer:** e2e
**Acceptance criterion mapped:** Port-preserving Keycloak discovery/authority plus the full browser return path

### TC-ISS-0063-03: callback state survives a callback-page reload and completes login
**Given:** A real Keycloak login flow has reached `/auth/callback` with a valid code/state pair
**When:** The callback page is reloaded once before the callback handler finishes
**Then:** The callback still completes, the app lands on `/`, and the authenticated workspace is visible instead of restarting the login loop
**Layer:** e2e
**Acceptance criterion mapped:** Persistent OIDC callback state across reload/remount

### TC-ISS-0063-04: suite is runnable as a real-browser executable test source
**Given:** The repository is opened in a workspace with Playwright configured for `web/tests/e2e`
**When:** TEST-RUNNER invokes the ISS-0063 spec file directly
**Then:** The executable source file at `web/tests/e2e/iss-0063-oidc-redirect-loop.e2e.spec.ts` is present and contains the runnable cases above
**Layer:** e2e
**Acceptance criterion mapped:** Runnable regression suite source exists
