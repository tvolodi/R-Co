## Acceptance Criteria

| ID | Criterion | Status |
|---|---|---|
| ISS-207-AC1 | retry requires changed cause; bare no-op retry rejected with 409 + hint | MUST |
| ISS-207-AC2 | retry-with-input re-presents trigger with corrected payload | MUST |
| ISS-207-AC3 | discard terminates instance as CANCELLED + dead_letter_items DISCARDED row | MUST |

---

## Test Cases

### TC1: bare retry of error instance (same def version) → 409 with hint

**Precondition:** Instance exists in ERROR status. DLQ item exists for it. Definition version
has NOT changed and no EXECUTION_CORRECTION event has been added.

**Action:** Call `retryConvergent(dlq_id)`.

**Expected:**
- Returns `DlqRetryError.RetryWithoutChange`.
- HTTP equivalent: `409 RETRY_WITHOUT_CHANGE`.
- Error message contains hint text.
- Instance remains in ERROR status.
- DLQ item remains unchanged.

---

### TC2: retry-with-input (corrected payload) → instance advances out of ERROR

**Precondition:** Instance exists in ERROR status. DLQ item exists for it.

**Action:** Call `retryWithInput(dlq_id, corrected_payload_json)` with a valid JSON object.

**Expected:**
- Returns `RetryConvergentResult` with status = "RETRYING".
- DLQ item is updated: `status='retrying'`, `original_payload` replaced.
- Instance is still ERROR (worker will pick it up) — DLQ item is now retrying.

---

### TC3: discard → instance CANCELLED, dead_letter_items row with DISCARDED

**Precondition:** Instance exists in ERROR status. DLQ item exists.

**Action:** Call `dlq_store.discard(dlq_id, actor_id)`.

**Expected:**
- Returns `DiscardResult`.
- Instance `status = 'CANCELLED'` in `instance_projections`.
- DLQ row deleted from `dead_letter_queue`.
- If `dead_letter_items` table exists: a row with `resolution='DISCARDED'`.

---

## Test Infrastructure

- Real PostgreSQL via `BPM_TEST_DB_URL`.
- Per-test UUIDs for instance_id, dlq_id, definition_id.
- Each test block creates its own fixtures and cleans up via `defer`.
- No mocks or stubs.
- If `BPM_TEST_DB_URL` is absent, all tests skip cleanly.
