# Test Spec: PD-07 — Definition retrieval

**Requirement:** PD-07 — The platform SHALL provide endpoints to: (a) retrieve a definition by UUID;
(b) list definitions with pagination and optional filters (name, status, stage); (c) retrieve the
currently ACTIVE version by definition name.
**Priority:** MUST
**Test layer:** unit (handler input-validation paths), integration (store-level + handler+DB paths)

---

## Shared preconditions

### Unit tests (`tests/unit/definition_retrieval_test.zig`)

- TC-PD-07-09, TC-PD-07-11, and TC-PD-07-13 are **pure handler-validation tests** — they exercise
  early-exit paths in `handleList` (`src/api/routes/definitions.zig`) that return before any store
  method is called.  No database connection is required.
- All other test cases (TC-PD-07-01 through TC-PD-07-08, TC-PD-07-10, TC-PD-07-12,
  TC-PD-07-14 through TC-PD-07-20) require a real PostgreSQL database.  They are stubbed with
  `error.SkipZigTest` and MUST be implemented as integration tests before PD-07 can advance to
  `TESTED` status.
- `std.testing.allocator` is used for all unit tests.  The `HandlerResult.body` slice is owned by
  the caller and freed with `defer alloc.free(result.body)` immediately after the call.

### Implementation discrepancy — TC-PD-07-10

The requirement (via API-06) and this spec require HTTP 422 when `page_size = 0`.  The current
implementation in `src/api/routes/definitions.zig` maps `page_size = 0` to the default value of 50
and proceeds to call `store.list()` without returning a 422 error:

```zig
if (ps == 0) break :blk 50;   // treats 0 as "use default", not as invalid
```

TC-PD-07-10 is therefore **skipped** until the handler is fixed.  See handoff result issues.

## Test Cases

### TC-PD-07-01: getActiveByName — ACTIVE version exists

**Given:** A store backed by a real database containing a process definition with `name = "proc-a"`
and `status = ACTIVE`.
**When:** `store.getActiveByName(allocator, "proc-a")` is called.
**Then:** Returns a `Definition` with `status = .ACTIVE` and `name = "proc-a"`.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — "retrieve the currently ACTIVE version by definition name"

---

### TC-PD-07-02: getActiveByName — no ACTIVE version returns DefinitionNotFound

**Given:** A store containing a definition with `name = "proc-b"` and `status = DRAFT` only (no
ACTIVE row).
**When:** `store.getActiveByName(allocator, "proc-b")` is called.
**Then:** Returns `DefinitionError.DefinitionNotFound`.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — "GIVEN no ACTIVE version, THEN HTTP 404" (store layer)

---

### TC-PD-07-03: getActiveByName — empty name string returns DefinitionNotFound

**Given:** A store with no definition having an empty name.
**When:** `store.getActiveByName(allocator, "")` is called.
**Then:** Returns `DefinitionError.DefinitionNotFound` (the SQL `WHERE name = $1 AND status =
'ACTIVE'` matches no rows).
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — store returns not-found for empty name

---

### TC-PD-07-04: list — stage filter narrows results

**Given:** A store containing two definitions: one with `stage = "intake"`, another with `stage =
"review"`.
**When:** `store.list(allocator, ListOpts{ .stage = "intake", .name = null, .status = null,
.after_created = null, .limit = 50 })` is called.
**Then:** Returns exactly one definition with `stage = "intake"`.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — "`GET /definitions` MUST support `?stage=` filter"

---

### TC-PD-07-05: list — stage filter null returns all

**Given:** A store containing two definitions with different stage values.
**When:** `store.list(allocator, ListOpts{ .stage = null, ... })` is called.
**Then:** Both definitions are returned.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — each filter is optional; null stage returns all entries

---

### TC-PD-07-06: list — combined name + status filter

**Given:** A store containing two definitions both named `"proc"`, one with `status = DRAFT` and
one with `status = ACTIVE`.
**When:** `store.list(allocator, ListOpts{ .name = "proc", .status = .ACTIVE, .stage = null,
.after_created = null, .limit = 50 })` is called.
**Then:** Returns exactly the one ACTIVE definition.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — "each [filter] is optional and combinable"

---

### TC-PD-07-07: list — combined name + stage filter

**Given:** A store containing two definitions both named `"proc"`, one with `stage = "intake"` and
one with `stage = "review"`.
**When:** `store.list(allocator, ListOpts{ .name = "proc", .stage = "intake", .status = null,
.after_created = null, .limit = 50 })` is called.
**Then:** Returns exactly the definition with `stage = "intake"`.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 — filters are combinable; `name + stage` combination

---

### TC-PD-07-08: handleList — valid cursor round-trip

**Given:** A store (real DB) with at least two definitions inserted in sequence.  The first call to
`handleList` returns a JSON body with a non-null `cursor` field.
**When:** The cursor is passed to a second call to `handleList`.
**Then:** The decoded cursor (base64url → decimal string → i64) equals the `created_at` µs value of
the last item returned on the first page; the second page contains only items created after that
timestamp.
**Layer:** integration
**Acceptance criterion mapped:** PD-07 / API-06 — pagination cursor encodes and decodes correctly

---

### TC-PD-07-09: handleList — invalid cursor returns HTTP 422

**Given:** `ListQueryParams{ .cursor = "not-base64!!", .name = null, .status = null, .stage = null,
.page_size = null }` and `std.testing.allocator`.
**When:** `handleList(&store, allocator, params)` is called.
**Then:** Returns `HandlerResult{ .status_code = 422, .body = "{\"error\":\"invalid cursor\"}" }`.
**Layer:** unit (pure — `decodeCursor` fails on the `!` characters before any store call)
**Acceptance criterion mapped:** PD-07 edge case — invalid cursor rejected with HTTP 422

---

### TC-PD-07-10: handleList — page_size=0 rejected *(DISCREPANCY — SKIPPED)*

**Given:** `ListQueryParams{ .page_size = 0 }`.
**When:** `handleList` is called.
**Then:** HTTP 422 with page_size validation message.
**Layer:** unit
**Acceptance criterion mapped:** PD-07 / API-06 — page_size must be validated
**Note:** SKIPPED. Current implementation maps `page_size = 0` to default 50 instead of returning
HTTP 422.  The handler must be updated to treat 0 as invalid before this test can pass.

### TC-PD-07-20: list — cursor pagination, second page does not overlap with first

**Given:** A store (real DB) with N > page_size definitions, each with a distinct `created_at`.
**When:** A first call returns a full page with a non-null cursor; a second call uses that cursor.
**Then:** All `id` values in the second page are absent from the first page (no overlap).
**Layer:** integration
**Acceptance criterion mapped:** PD-07 / API-06 — cursor-based pagination returns non-overlapping
pages ordered by `created_at ASC`
