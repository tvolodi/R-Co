# ISS-206 Test Spec: Engine token multiset + persisted parallel-join counters

**Requirement:** ISS-206 — Engine token multiset + persisted parallel-join counters
**Test layer:** Unit (pure logic) + Integration (DB round-trip)
**Design artefact:** src/design/iss206_token_multiset_join_counters.md

---

## MUST test cases

### TC-ISS206-01: PARALLEL split assigns deterministic token_id to each branch

Given: A PARALLEL_GATEWAY split node with 2 outgoing edges
When: A token arrives at the split
Then: Each output token has a non-null token_id (16-char hex string)
And: token_ids are distinct from each other
And: token_ids are deterministic (same inputs produce same outputs)

Covered by: TC-EE-06-01 through TC-EE-06-05 (existing in transition.zig)

### TC-ISS206-02: Join advances when all branches arrive

Given: A PARALLEL_GATEWAY join with 3 incoming edges
When: All 3 tokens arrive at the join (across multiple transition calls)
Then: The join fires, producing exactly 1 merged token on the outgoing edge
And: join_counters shows received_count == expected_from_branches before firing
And: join_counters is reset to 0/0 after firing

Covered by: TC-EE-07-05 (existing in tests/unit/test_ee07_parallel_join.zig)

### TC-ISS206-03: Cancelled branch subtracts from join requirement

Given: A parallel join expecting 3 branches, with 1 branch already cancelled
When: The remaining 2 branches arrive
Then: The join fires (expected = 3 - 1 = 2 branches)
And: The PARALLEL_JOIN event records the cancelled branch

Covered by: TC-EE-07-01 (existing in transition.zig)

### TC-ISS206-04: Replay round-trip equality

Given: A sequence of transition() calls producing state with join_counters
When: The same event sequence is replayed with the same initial state
Then: The final state has identical active_tokens and join_counters

Covered by: TC-EE-02-11 (existing determinism test in transition.zig)
