# Test Spec: ISS-102 — `tasks.claimed_by` and Real Claim Path

**Requirement:** ISS-102 — The platform SHALL provide an atomic `POST /tasks/:id/claim` endpoint that records `claimed_by` and enforces that only the claimer (or a directly USER-assigned worker) may subsequently complete a task.  
**Priority:** MUST  
**Test layer:** integration

---

## Acceptance Criteria (verbatim from requirement)

1. Claiming a PENDING, unclaimed task sets `claimed_by` to the actor's `user_id` and returns the updated task.
2. When two workers concurrently claim the same task, exactly one succeeds (HTTP 200); the other receives HTTP 409 / `TASK_ALREADY_CLAIMED`.
3. Claiming a task whose `claimed_by IS NOT NULL` returns HTTP 409 / `TASK_ALREADY_CLAIMED`.
4. Claiming a task whose `status != 'PENDING'` returns HTTP 409 / `TASK_NOT_PENDING`.
5. A TASK_WORKER whose `user_id` matches `claimed_by` may complete the task (HTTP 200).
6. A TASK_WORKER whose `user_id` does NOT match `claimed_by` receives HTTP 403 / `UNAUTHORIZED_COMPLETE`.
7. A TASK_WORKER whose `user_id` matches `assignee_ref` on an unclaimed USER-assigned task may complete it (HTTP 200).
8. A TASK_WORKER whose `user_id` does NOT match `assignee_ref` on an unclaimed USER-assigned task receives HTTP 403 / `UNAUTHORIZED_COMPLETE`.

---

## Test Cases

### TC-ISS-102-01: Happy path — claim succeeds and sets claimed_by

**Given:** A PENDING task with `claimed_by IS NULL` in the database.  
**When:** `TaskStore.claimTask(task_id, worker_a)` is called.  
**Then:**
- The function returns successfully with the updated `Task`.
- The returned `task.claimed_by` equals `worker_a`'s UUID.
- The returned `task.status` is still `PENDING` (claim does not change status).
- The database row reflects `claimed_by = worker_a`.

**Layer:** integration  
**Acceptance criterion mapped:** AC-1  
**Implemented by:** `tests/integration/iss102_claim_test.zig` — test `TC-ISS-102-01: happy path — claimTask sets claimed_by`

---

### TC-ISS-102-02: Concurrent double-claim — exactly one winner

**Given:** A PENDING unclaimed task.  
**When:** Two goroutines/threads simultaneously call `TaskStore.claimTask` on the same `task_id`, with distinct `worker_id` values.  
**Then:**
- Exactly one thread receives a successful `Task` result (the winner).
- The other thread receives `ClaimError.AlreadyClaimed`.
- The `claimed_by` column in the database is non-NULL and equals the winner's `worker_id`.

**Layer:** integration  
**Acceptance criterion mapped:** AC-2  
**Implemented by:** `tests/integration/iss102_claim_test.zig` — test `TC-ISS-102-02: concurrent double-claim — exactly one wins`

---

### TC-ISS-102-03: Claim on already-claimed task returns AlreadyClaimed

**Given:** A PENDING task with `claimed_by = worker_a`.  
**When:** `TaskStore.claimTask(task_id, worker_b)` is called.  
**Then:**
- The function returns `ClaimError.AlreadyClaimed`.
- The database row is unchanged (`claimed_by` remains `worker_a`).

**Layer:** integration  
**Acceptance criterion mapped:** AC-3  
**Implemented by:** `tests/integration/iss102_claim_test.zig` — test `TC-ISS-102-03: claim on already-claimed task returns AlreadyClaimed`
