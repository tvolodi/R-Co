# Test Spec: ISS-106 — webhook_deliveries transactional-outbox table formalization

**Requirement:** ISS-106 (Webhook deliveries transactional-outbox table formalization)
**Design:** `src/design/iss-106-webhook-outbox.md`
**Migration under test:** `migrations/085_iss106_webhook_deliveries_outbox.sql`
**Test layer:** integration (real PostgreSQL via `BPM_TEST_DB_URL`)
**Test file:** `tests/integration/iss106_webhook_outbox_test.zig`

---

## Scope

ISS-106 is a **schema/migration** requirement. The migration is an additive, idempotent
reconciliation of the pre-existing `webhook_deliveries` table to the outbox contract:

- adds the `attempt INTEGER NOT NULL DEFAULT 0` column,
- remaps legacy lowercase status values and installs the uppercase status domain CHECK
  `webhook_deliveries_status_check` over `(PENDING, DELIVERED, FAILED, RETRYING)`,
- re-asserts the worker-claim index `idx_wd_status_next_attempt` on `(status, next_attempt_at)`.

This spec proves the **table shape and constraints produced by the migration** against a
real PostgreSQL instance. It does **NOT** test the transactional-outbox INSERT path or the
`FOR UPDATE SKIP LOCKED` worker-claim query — those are **ISS-205** and are explicitly
deferred by the architecture backlog and the ISS-106 design (§Scope, "OUT OF SCOPE").

---

## Fixture strategy

Mirrors the established schema-migration test idiom (`iss101_timers_failed_status_test.zig`):

- Each test provisions its **own per-test tenant schema** via `provisionTenantSchema`, using a
  freshly generated random UUID tenant id (`randomUuidStr`). No shared mutable fixture state.
- A direct `pg.Conn` is opened with `search_path` set to that schema, so all table names are
  **unqualified** (matching the per-tenant migration application model).
- The schema (and its tracking rows) is dropped via `defer cleanupTenant(...)` — cleanup runs
  even on test failure.
- `webhook_deliveries.subscription_id` is a `NOT NULL` FK to `webhook_subscriptions(id)`, whose
  `owner_id` is a `NOT NULL` FK to `users(id)`. Each test therefore creates a throwaway `users`
  row and a throwaway `webhook_subscriptions` row (both with per-test UUIDs) inside the
  provisioned schema; both are removed when the schema is dropped on cleanup.
- The test **fails clearly** if `BPM_TEST_DB_URL` is absent (`testDbUrl` returns
  `error.MissingTestDatabaseUrl` with a printed diagnostic).
- No `error.SkipZigTest` anywhere — every assertion is a real, runnable integration check.

## Assertion-to-acceptance-criterion map

| # | Test case | Asserts | ISS-106 acceptance criterion |
|---|---|---|---|
| 1 | `TC-ISS-106-01` attempt column shape | `information_schema.columns` (filtered `table_schema = current_schema()`) shows `attempt` with `data_type = integer`, `is_nullable = NO`, `column_default = 0` | Contract column `attempt` added as `INTEGER NOT NULL DEFAULT 0` (design Step 1) |
| 2 | `TC-ISS-106-02` valid status domain accepted | Inserting one `webhook_deliveries` row for **each** of `PENDING, DELIVERED, FAILED, RETRYING` succeeds and round-trips | status domain `(PENDING, DELIVERED, FAILED, RETRYING)` accepted by `webhook_deliveries_status_check` (design Step 4) |
| 3 | `TC-ISS-106-03` out-of-domain status rejected | Inserting `status = 'BOGUS'` and legacy lowercase `status = 'pending'` are each rejected with a server-side CHECK violation; via SAVEPOINT the connection survives and no row persists | `webhook_deliveries_status_check` rejects values outside the uppercase domain, including legacy lowercase values (design Step 4) |
| 4 | `TC-ISS-106-04` worker-claim index present | `pg_indexes` (filtered `schemaname = current_schema()`) contains `idx_wd_status_next_attempt`, and its definition covers columns `status` and `next_attempt_at` | Worker-claim index `(status, next_attempt_at)` exists, not duplicated (design Step 5) |
| 5 | `TC-ISS-106-05` full-contract round-trip | A row written with the full contract column set (`id` as delivery_id, `subscription_id`, `event_id`, `status`, `attempt`, `next_attempt_at`, `last_error`, `created_at`) reads back with every value intact | Full outbox contract column set present and persists correctly (design §"ISS-106 contract vs current state") |

## Explicit non-goals (ISS-205 — NOT tested here)

- Transactional-outbox INSERT that enqueues a delivery in the same transaction as the event commit.
- `FOR UPDATE SKIP LOCKED` worker-claim query.
- Exponential back-off ladder / `next_attempt_at` scheduling logic.
- Any dispatcher/worker Zig behaviour. ISS-106 writes no Zig source; this test exercises DDL only.

---

## Pass criteria

All five test cases pass against a live PostgreSQL reached through `BPM_TEST_DB_URL`, with each
test operating in its own freshly provisioned tenant schema and cleaning up on completion.
