# Test Spec: PD-06 — Edge conditions

**Requirement:** PD-06 — Edge conditions (MUST) — Edges originating from EXCLUSIVE_GATEWAY nodes
SHALL carry a CEL condition expression (string). The platform SHALL validate that the expression is
syntactically valid CEL at definition creation time.

**Priority:** MUST
**Test layer:** unit (`validateEdgeConditions`, `isValidCelSyntax`)

---

## Shared preconditions

### Unit tests (`tests/unit/graph_edge_conditions_test.zig`)

- Tests call `graph.validateEdgeConditions(allocator, graph)` directly — no DB required.
- `isValidCelSyntax` is a private helper called internally by `validateEdgeConditions`; its
  behaviour is exercised through edge-condition tests that trigger CHK-EC-06.
- Each graph is constructed inline as arrays of `GraphNode` and `GraphEdge` literals on the stack.
- `std.testing.allocator` is used; all `ValidationResult` values are freed per memory contract:
  `for (result.violations) |v| alloc.free(v.message); alloc.free(result.violations);`
- The helper `hasCode(violations, code)` is used to assert violation codes without depending on
  message text or ordering.

### CHK-EC check codes

| Code | Check |
|------|-------|
| CHK-EC-01 | Edge from non-EXCLUSIVE_GATEWAY node MUST NOT have a condition |
| CHK-EC-02 | Edge from non-EXCLUSIVE_GATEWAY node MUST NOT have `is_default = true` |
| CHK-EC-03 | Non-default outgoing edge from EXCLUSIVE_GATEWAY MUST have a non-empty condition |
| CHK-EC-04 | An edge with `is_default = true` MUST NOT also carry a condition expression |
| CHK-EC-05 | At most one outgoing edge per EXCLUSIVE_GATEWAY may have `is_default = true` |
| CHK-EC-06 | Any condition string present on an EXCLUSIVE_GATEWAY edge MUST be valid CEL syntax |

## Test Cases

### TC-PD-06-01: EXCLUSIVE_GATEWAY with valid CEL conditions on all outgoing edges → valid

**Given:** a graph with an EXCLUSIVE_GATEWAY node whose two outgoing edges both carry valid CEL
condition strings (`"x > 0"` and `"x <= 0"`).
**When:** `validateEdgeConditions()` is called.
**Then:** result is valid; zero violations.
**Layer:** unit
**Acceptance criterion mapped:** PD-06 — "Edges originating from EXCLUSIVE_GATEWAY nodes SHALL carry
a CEL condition expression." (positive path — all non-default edges have conditions)

### TC-PD-06-16: graph with multiple simultaneous PD-06 violations → all violations collected (non-early-exit)

**Given:** a graph containing:
  - a HUMAN_TASK → END edge with `condition = "x > 0"` (CHK-EC-01)
  - an EXCLUSIVE_GATEWAY → END edge with `condition = null` and `is_default = false` (CHK-EC-03)
**When:** `validateEdgeConditions()` is called.
**Then:** result is invalid; both `EDGE_CONDITION_NOT_ALLOWED` and `EDGE_MISSING_CONDITION` are
present in the violations list; `violations.len >= 2`.
**Layer:** unit
**Acceptance criterion mapped:** PD-06 — all checks are exhaustive (no early exit after first
failure).
