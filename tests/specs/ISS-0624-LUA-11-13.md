**Run:** WF03-GH591-20260809
**Requirements:** LUA-11 (`platform.read_variable` / `platform.write_variable`), LUA-13 (`platform.log`)
**Backlog:** ISS-0624 / GH-591

## Purpose

This spec documents the unit-test tranche for the LUA-11 and LUA-13 production
fix that lands ExecutionContext's `trace_id`, `pending_writes`,
`structured_logger`, and `instance_state` fields, together with the
`extractValueInto` helper, the `Writer` swap-in injection point on
`StructuredLogger`, and the LUA-11/13 host-API bodies (`read_variable.zig`,
`write_variable.zig`, `log.zig`).

The tranche closes the ISS-0153-era stubs that returned `nil` after the
capability gate passed.

The canonical requirement-level specs (`tests/specs/LUA-11.md`,
`tests/specs/LUA-13.md`) describe the integration-layer acceptance criteria.
This spec describes the **unit** layer that exercises the same MUSTs against
the linked LuaJIT sandbox without a running PostgreSQL.

## Test cases

### LUA-11 unit cases

#### TC-ISS-0624-LUA-11-01: write_variable on success lands in instance_state.variables
**Given:** A fresh fixture with VARIABLE_READ + VARIABLE_WRITE capabilities.
**When:** Script calls `platform.write_variable('status', 'done')` and returns.
**Then:** `r.success == true`, `instance_state.variables.get("status")?.string == "done"`.

#### TC-ISS-0624-LUA-11-02: read_variable of missing key returns nil
**Given:** A fresh fixture.
**When:** Script does `local v = platform.read_variable('absent') return v == nil`.
**Then:** `r.success == true`, `r.value.?.boolean == true`.

#### TC-ISS-0624-LUA-11-03: read_variable returns the stored value
**Given:** A fixture; a first script writes `'greeting' = 'hello'` and commits.
**When:** A second script does `local v = platform.read_variable('greeting') return v`.
**Then:** `r.success == true`, `r.value.?.string == "hello"`.

#### TC-ISS-0624-LUA-11-04: explicit platform.fail discards pending writes
**Given:** A fixture pre-seeded with `'x' = '1'` from a prior script.
**When:** Script does `platform.write_variable('y', '2') platform.fail('abort')`.
**Then:** `r.success == false`, `error_kind == .ExplicitFailure`, `'y' NOT in instance_state.variables`, `'x' unchanged`.

#### TC-ISS-0624-LUA-11-05: runtime error discards pending writes
**Given:** A fixture with `'value' = 'original'`.
**When:** Script does `platform.write_variable('value', 'new')` then triggers a Lua runtime error.
**Then:** `r.success == false`, `error_kind == .RuntimeError`, `'value'` still `'original'`.

#### TC-ISS-0624-LUA-11-06: three writes to the same key: final value wins
**Given:** A fresh fixture.
**When:** Script does three writes to `'k'` with values `'a'`, `'b'`, `'c'`.
**Then:** `instance_state.variables.get("k")?.string == "c"`.

#### TC-ISS-0624-LUA-11-07: read-after-write within an execution
**Given:** A fresh fixture; script seeds via prior script: `'c' = 5`.
**When:** Script does `local x = platform.read_variable('c') platform.write_variable('c', x+1)`.
**Then:** `instance_state.variables.get("c")?.number == 6.0`.

#### TC-ISS-0624-LUA-11-08: write a table, recursive table is preserved
**Given:** A fresh fixture.
**When:** Script does `platform.write_variable('row', { x = 1, y = 2 })`.
**Then:** `instance_state.variables.get("row")` is `.table`; iterating yields `x == 1`, `y == 2`.

#### TC-ISS-0624-LUA-11-09: write nil to an existing key drops it
**Given:** A fixture pre-seeded with `'drop' = 'present'` from a prior script.
**When:** Script does `platform.write_variable('drop', nil)`.
**Then:** `r.success == true`, `instance_state.variables.get("drop") == null`.

#### TC-ISS-0624-LUA-11-10: two scripts on different instance_ids do not bleed
**Given:** Two fixtures with distinct instance_ids `iss0624-lua-11-tc10-a` and `iss0624-lua-11-tc10-b`.
**When:** Each script writes its own `'who' = '<self>'` to its own context.
**Then:** `fx_a.state.variables.get("who")?.string == "A"`, `fx_b.state.variables.get("who")?.string == "B"`.

#### TC-ISS-0624-LUA-11-11: capability denial still fires (variable:write missing)
**Given:** A fixture with VARIABLE_READ only.
**When:** Script does `platform.write_variable('k', 'v')`.
**Then:** `r.success == false`, `error_kind == .CapabilityDenied`.

#### TC-ISS-0624-LUA-11-12: pending_writes field defaults to null; write is a no-op
**Given:** A fixture built without installing `pending_writes` (legacy / default path).
**When:** Script does `platform.write_variable('legacy', 'v')`.
**Then:** `r.success == true`, `instance_state.variables.get("legacy") == null` (no panic, no error).

### LUA-13 unit cases

#### TC-ISS-0624-LUA-13-01: platform.log INFO writes entry with trace_id + instance_id + actor_id
**Given:** A fixture with a capture-writer logger installed; `trace_id = "iss0624-trace-tc01"`, `instance_id = "iss0624-lua-13-tc01-info"`, `actor_id = "iss0624-tc01"`.
**When:** Script does `platform.log('INFO', 'msg', {})`.
**Then:** Captured buffer contains: `"INFO"`, `"msg"`, `instance_id`, `actor_id`, `trace_id`.

#### TC-ISS-0624-LUA-13-02: WARN / ERROR / DEBUG levels are recorded
**Given:** A fixture with a capture-writer logger.
**When:** Script does three calls of `platform.log(<level>, 'msg', {})` with levels `WARN`, `ERROR`, `DEBUG`.
**Then:** Captured buffer contains the three level strings; each entry is the right level.

#### TC-ISS-0624-LUA-13-03: context table is captured
**Given:** A fixture with a capture-writer logger.
**When:** Script does `platform.log('INFO', 'msg', { order_id = 'X', amount = 1.5 })`.
**Then:** Captured buffer contains `"order_id"`, `"X"`, `"amount"`, `"1.5"`.

#### TC-ISS-0624-LUA-13-04: missing third arg: context = null, no panic
**Given:** A fixture with a capture-writer logger.
**When:** Script does `platform.log('INFO', 'msg')` (no third arg).
**Then:** `r.success == true`, captured buffer contains `"INFO"`/`"msg"`; no panic, no error.

#### TC-ISS-0624-LUA-13-05: bogus log level raises an error
**Given:** A fixture with a capture-writer logger.
**When:** Script does `platform.log('BOGUS', 'msg', {})`.
**Then:** `r.success == false`, `error_kind == .RuntimeError`, `error_message` contains `"invalid log level"`.

#### TC-ISS-0624-LUA-13-06: missing audit:log capability is denied
**Given:** A fixture with AUDIT_LOG not granted.
**When:** Script does `platform.log('INFO', 'msg', {})`.
**Then:** `r.success == false`, `error_kind == .CapabilityDenied`.

#### TC-ISS-0624-LUA-13-07: per-script trace_id isolation
**Given:** Two fixtures with distinct `trace_id`s.
**When:** Each script does `platform.log('INFO', 'msg', {})` under its own context.
**Then:** Captured buffer A contains `trace_id_a` but NOT `trace_id_b`; buffer B the inverse.

#### TC-ISS-0624-LUA-13-08: structured_logger == null: fail-open no-op
**Given:** A fixture built with `structured_logger = null`.
**When:** Script does `platform.log('INFO', 'msg', {})`.
**Then:** `r.success == true`; no panic; capture buffer (if any) is empty.

#### TC-ISS-0624-LUA-13-09: multiple log calls in sequence, all captured in invocation order
**Given:** A fixture with a capture-writer logger.
**When:** Script does `platform.log('INFO', ...)`, `platform.log('WARN', ...)`, `platform.log('ERROR', ...)`.
**Then:** Captured buffer contains the three entries in order: index(`INFO`) < index(`WARN`) < index(`ERROR`).

### Type-shape assertions (regression — non-MUST)

#### TC-ISS-0624-type-01: StructuredLogger.Writer field is `*const fn` (runtime-known)
**Given:** The post-rework `StructuredLogger`.
**When:** `@typeInfo(@TypeOf(logger.writer)).pointer` is inspected.
**Then:** `pointer.size == .one`, `pointer.child == Writer`, `pointer.is_const == true`.
**Why:** Documents the BLOCKER fix per the rework diagnosis at
`docs/issue-reports/WF03-GH591-20260809-step-03-ISSUE-FIXER-REWORK-DIAGNOSIS.yaml`.
Without the `*const Writer` pointer, the field would be comptime-only in Zig 0.16
and `@sizeOf` would fail; this test guards against reverting the fix.

#### TC-ISS-0624-type-02: ExecutionContext exposes the four new fields
**Given:** The post-rework `ExecutionContext`.
**When:** `@hasField(ContextType, "trace_id" / "pending_writes" / "structured_logger" / "instance_state")` is checked.
**Then:** All four checks are true.
**Why:** Documents design §2 — adding these fields is the prerequisite for the
rest of the LUA-11/13 fix landing. A future refactor that drops any of them
would break every other case in this spec.

## Fixture pattern (per-test UUID isolation)

Each test creates its own `CapabilitySet`, `ExecutionContext`, `InstanceState`,
and (for LUA-13) `StructuredLogger`. There is no shared state across tests.

`TEST_INSTANCE_BASE_LUA11 = "iss0624-lua-11-"` and
`TEST_INSTANCE_BASE_LUA13 = "iss0624-lua-13-"` are concatenated with a unique
suffix (`freshFixtureLUA11("tc01-write-success")` → `instance_id =
"iss0624-lua-11-tc01-write-success"`).

`trace_id` follows the same pattern: `"iss0624-trace-<suffix>"`.

Cleanup is unconditional: `defer fx.deinit();` at the top of every test, plus
`defer r.deinit(testing.allocator);` after every `executeScript` call.

## Environment failure (defensive guard)

`error.SkipZigTest` is used as a short-circuit when `executeScript` returns an
**error** (i.e. the linked LuaJIT sandboxed-state constructor returned `null`,
the empirical signal that the static archive is unavailable in this build
profile). The guard is per `executeScript` call inside the test body, NOT at
the test top — every other assertion (comptime type-shape, fixture
construction) still runs even when LuaJIT is unavailable.

The guard does NOT mask production failures: if `executeScript` returns a
valid `ScriptResult` with `success == false` (the script itself raised a Lua
error), the test continues to assertions and reports a failure. This is the
intended behaviour for the TC-09 / TC-05 / TC-11 cases: they assert on the
shape of the error the production code is supposed to surface.

- The LUA-08 instruction limiter, LUA-09 memory limiter, LUA-10 watchdog: pre-existing regression tests at `tests/integration/*` and `src/lua/limiter_wiring_test.zig`; no scope expansion in this tranche.
- Backlog entries for `BPM_TEST_DB_URL` requirement: this tranche is unit-only and uses no DB; no env-failure precondition.
