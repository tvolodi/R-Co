# Test Spec: ISS-0121 — TestHarness per-test UUID isolation helper (GitHub #387)

**Requirement:** ISS-0121 / GitHub #387 — eliminate hardcoded UUID literals in integration-test fixtures by exposing two helpers on the shared `TestHarness` struct that produce fresh, cryptographically random, RFC 4122 v4 UUIDs on every call. The refactor removes the T010 hardcoded-UUID collision class documented in `docs/guides/test_infrastructure_guide.md §9` without introducing any new public-API surface area or shared mutable state in `tests/integration/helpers.zig`.

**Priority:** MUST. ISS-0121 is a BLOCKER for the integration-test isolation lint gate: the current Step 3 implementation introduced the two helpers but does not yet ship a regression suite that pins the contract, so a future refactor of `TestHarness` or `bpm.uuid` could silently break the 258+ T010-targeted migration sites without any failing test to catch it.

**Test layer:** integration (real PostgreSQL via `BPM_TEST_DB_URL` for TC-07; the other six test cases run with only the uninitialised `TestHarness` struct, exercising the helper methods directly without a DB connection — they are deterministic and run under `zig build test` as well).

## Test cases

### TC-ISS-0121-01 — `newUuid` returns a non-zero UUID

**Given:**
- A `TestHarness` value exists in scope (any uninitialised value; `newUuid` reads neither `conn` nor `allocator`).

**When:**
The test calls `h.newUuid()` and inspects the returned 16-byte value.

**Then:**
- The 16 bytes MUST NOT be all zero (`bpm.uuid.Uuid != [_]u8{0} ** 16`).
- A test that flipped the random source to a constant-zero generator would fail this check — the assertion is the minimum sanity gate against a broken `fillRandomBytes` dispatch or a dead-code path.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "Each invocation returns a fresh RFC 4122-compatible UUID value suitable for a distinct test fixture."

**Isolation:** no DB connection, no fixture state; the test simply calls the helper and inspects the bytes.

---

### TC-ISS-0121-02 — `newUuid` called twice yields distinct values

**Given:**
- A `TestHarness` value exists in scope.

**When:**
The test calls `h.newUuid()` twice (`u1`, `u2`) and compares the byte arrays element-wise.

**Then:**
- `u1 != u2` (compared with `!std.mem.eql(u8, &u1, &u2)`).
- A test that accidentally seeded the generator with a fixed value, or that returned a process-global singleton UUID, would fail this check. The contract requires independent random bytes on every call.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "Each invocation returns a fresh ... value" and §3 "Generation ... is infallible and allocation-free, so it is suitable for hot fixtures in MUST tests."

**Isolation:** no DB connection; the two calls happen in a single test block so no cross-test state is involved.

### TC-ISS-0121-03 — `newUuid` is RFC 4122 v4 compliant (version + variant bits)

**Given:**
- A `TestHarness` value exists in scope.

**When:**
The test calls `h.newUuid()`, then inspects the bytes that encode the UUID version and variant under RFC 4122 §4.4:
- Byte 6's high nibble = `0x4` (version 4, randomly generated).
- Byte 8's top two bits = `0b10` (RFC 4122 variant).

**Then:**
- `(u[6] & 0xF0) == 0x40`.
- `(u[8] & 0xC0) == 0x80`.
- These are the same checks `tests/integration/iss203_idempotency_keys_test.zig` and the inline test in `src/util/uuid.zig` apply, so a regression in `generateUuidV4BytesInto`'s version/variant masking is caught here before it can produce malformed UUIDs that downstream validation rejects.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "Each invocation returns a fresh RFC 4122-compatible UUID value."

**Isolation:** no DB; one test block, one call.

### TC-ISS-0121-04 — `newUuidString` returns a 36-byte hyphenated lowercase string matching the RFC 4122 regex

**Given:**
- A `TestHarness` value exists in scope and a `std.testing.allocator` is available.

**When:**
The test calls `h.newUuidString(allocator)`, captures the returned `[]u8`, and validates:
- Length is exactly 36 bytes.
- Positions 8, 13, 18, 23 are ASCII hyphens.
- Every other position is a lowercase hex digit (`0-9`, `a-f`).
- Character at position 14 is the version-4 nibble (`'4'`).
- Character at position 19 is one of `'8'`, `'9'`, `'a'`, `'b'` (the high nibble of `u[8]` after variant masking — i.e. the variant identifier characters).

**Then:**
- All checks pass. The string satisfies the canonical RFC 4122 v4 format: `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`.
- A test that bypassed the trace-side `generateUuidV4` formatter (e.g. returned a 36-byte raw random buffer) would fail the dash-position and version-character checks.
- The string is `defer allocator.free()`-d inside the test block.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "`newUuidString` obtains a fresh UUID through `newUuid`, allocates its canonical lower-case hyphenated representation, and transfers ownership of that byte slice to the caller" and §3 "allocate exactly one caller-owned byte slice containing the canonical 36-byte hyphenated representation."

**Isolation:** no DB; per-test allocation freed at block exit.

### TC-ISS-0121-05 — `newUuidString` called twice yields distinct strings

**Given:**
- A `TestHarness` value exists in scope and `std.testing.allocator` is available.

**When:**
The test calls `h.newUuidString(allocator)` twice, captures the two `[]u8` results, and compares them with `!std.mem.eql(u8, s1, s2)`.

**Then:**
- `s1 != s2`. Both strings are `defer allocator.free()`-d inside the test block.
- A test that returned a process-global constant would fail this check. The contract requires a fresh value per call.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "Each invocation returns a fresh ... value."

**Isolation:** no DB; both calls happen in a single test block.

### TC-ISS-0121-06 — 1000 successive `newUuid` calls are all pairwise distinct (entropy sanity)

**Given:**
- A `TestHarness` value exists in scope and `std.testing.allocator` is available.

**When:**
The test calls `h.newUuid()` 1000 times into a `std.ArrayList(bpm.uuid.Uuid)` owned by the test allocator. After the loop, the test walks every pair (i, j) with `i < j` and asserts the byte arrays are not equal.

**Then:**
- All 1000 returned UUIDs are pairwise distinct. The 128-bit CSPRNG output has a vanishingly small collision probability at N=1000 (`~N^2 / 2^129`), so any duplicate is a definitive failure of either the random source or the version/variant masking.
- The test must NOT rely on `error.SkipZigTest` — this is a MUST coverage gate. A 1000-iteration loop is cheap (< 1 ms on a modern CSPRNG) and the O(N²) pair check is bounded to 499 500 comparisons.
- The `ArrayList` is `defer array.deinit(allocator)`-d at block exit.

**Layer:** unit-style (no DB).

**Acceptance criterion mapped:** contract §3 "Each invocation returns a fresh ... value" + design §11 "Random collision: Two fixtures could theoretically receive the same ID" mitigation — the standard cryptographically secure 128-bit source. The 1000-element loop is the practical sanity check that backs the negligible-collision claim.

**Isolation:** no DB; the list is created and freed inside one test block.

### TC-ISS-0121-07 — Round-trip: `newUuidString` round-trips through `audit_entries.resource_id TEXT`

**Given:**
- `TestHarness.init()` succeeds (real `BPM_TEST_DB_URL`, real PostgreSQL, harness transaction is open).
- A per-test resource_type string (`'iss0121.roundtrip.tc07'`) is chosen so the row is trivially distinguishable from any other test's audit history.

**When:**
The test calls `h.newUuidString(allocator)` to obtain a fresh 36-character hyphenated UUID, INSERTs that string into `audit_entries.resource_id` (with all other required columns populated: `audit_id`, `tenant_id`, `actor_id`, `action`, `resource_type`, `timestamp`, `before_state`, `after_state`, `trace_id`), then SELECTs `resource_id` back and compares to the generated string.

**Then:**
- The INSERT succeeds (the `trg_bpm_audit_apply_chain_hash` BEFORE INSERT trigger fires; the row's `chain_hash` is a 64-character lowercase hex or NULL, per the migration 1107 EXCEPTION guard).
- The SELECTed `resource_id` byte-equals the originally generated string (`std.mem.eql(u8, &selected, &generated)`).
- The harness's `defer h.deinit()` rolls back the transaction, so the row never reaches the schema.
- A test that produced non-canonical strings (wrong case, missing dashes, wrong length) would fail the `expectEqualStrings` assertion; a test that bypassed the harness and INSERTed via raw SQL would lose the per-test transaction rollback and fail the test-isolation contract.

**Layer:** integration (real PostgreSQL).

**Acceptance criterion mapped:** contract §3 "`newUuidString` obtains a fresh UUID through `newUuid`, allocates its canonical lower-case hyphenated representation, and transfers ownership of that byte slice to the caller" — the round-trip proves the helper output is acceptable as a real `$1` parameter to a `TEXT` column that downstream audit-trigger code will compute a SHA-256 over.

**Isolation:** per-test resource_type, per-test audit_id, per-test tenant UUID; harness transaction rolls back at `h.deinit()`.

## Isolation and security contract

- TC-01..TC-06 do NOT call `TestHarness.init()` and therefore do NOT require `BPM_TEST_DB_URL`. They instantiate an uninitialised `TestHarness` value (`var h: TestHarness = undefined;`) and call the helpers on it; both helpers `_ = self;` and read neither `h.conn` nor `h.allocator`, so the uninitialised state is safe.
- TC-07 calls `TestHarness.init()`. Missing `BPM_TEST_DB_URL` returns `error.MissingTestDatabaseUrl` from `TestHarness.init()` — the test block propagates that error rather than swallowing it as `error.SkipZigTest` (FORBIDDEN on MUST requirements per `docs/anti-patterns.md`).
- All fixture SQL in TC-07 uses PostgreSQL placeholders (`$1::text`, `$2::uuid`, etc.) — no string interpolation of user data into SQL.
- Per-test UUIDs are used for: every `newUuid()` / `newUuidString()` call (every call returns a distinct value, so callers do not need a separate per-test alias). The all-zero UUID remains the platform's default-tenant sentinel and is NOT generated by either helper.
- No mocks, no stubs, no in-memory database, no `error.SkipZigTest`.
- Lint baseline impact: `tools/lint_test_isolation.py` only flags hardcoded UUID literals inside `tests/integration/*.zig`; the new test file uses no hardcoded UUID literals and therefore contributes zero T010 / T020 / T030 / T040 / T050 / T060 findings.
