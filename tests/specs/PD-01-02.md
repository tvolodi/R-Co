# Test Spec: PD-01 & PD-02 — Create definition and Graph validation

**Requirement:** PD-01 — Create definition (MUST) — Authorised callers SHALL be able to create a
new process definition by submitting a name, version string, description, and a definition graph
(nodes + edges as JSON). The platform assigns a UUID and sets status = DRAFT.

**Requirement:** PD-02 — Graph validation (MUST) — On creation or update, the platform SHALL
validate: graph is a directed graph with exactly one START node and at least one END node; all edge
source/target references point to existing nodes; no isolated nodes exist; no duplicate node IDs
within a definition; no cycles exist in paths that do not pass through a gateway node; node count
does not exceed 500 and edge count does not exceed 2,000.

**Priority:** MUST  
**Test layer:** integration (store.create() end-to-end path against a real PostgreSQL database)

---

## Shared preconditions

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()`).
- A `definition.Store` is created with a live `Pool`.
- A fixed `created_by` UUID `00000000-0000-0000-0000-000000000099` is used in all tests.
- Each test that writes to the database cleans up its row on exit.

---

## Test Cases

### TC-PD-01-01: Create valid definition — UUID assigned, status = DRAFT

**Given:** a valid `CreateParams` with name = `"TC-PD-01-01 Process"`, version = `"1.0.0"`,
description = `"test definition"`, and a minimal valid graph (START → USER_TASK → END).  
**When:** `store.create()` is called.  
**Then:**
- Returns a `Definition` (no error).
- `definition.id` is non-zero (platform-assigned UUID).
- `definition.status == .DRAFT`.
- `definition.name` equals `"TC-PD-01-01 Process"`.
- `definition.version` equals `"1.0.0"`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-01 — "the platform returns HTTP 201 with the assigned UUID,
`status = DRAFT`, and all submitted fields."

---

### TC-PD-01-02: Create with same name + version → DuplicateNameVersion

**Given:** a definition named `"TC-PD-01-02 Process"` / `"2.0.0"` has already been created.  
**When:** `store.create()` is called again with the same name + version.  
**Then:** returns `DefinitionError.DuplicateNameVersion`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-01 — "Two definitions with the same name and version string
MUST be rejected with HTTP 409."

---

### TC-PD-01-03: Create with invalid graph (no START node) → GraphValidationFailed

**Given:** `CreateParams` with a graph that contains no START node (one USER_TASK and one END).  
**When:** `store.create()` is called.  
**Then:** returns `DefinitionError.GraphValidationFailed`;
`store.lastViolations()` contains a violation with code `"MISSING_START_NODE"`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-01 — "The definition graph MUST be a JSON object with a
`nodes` array and an `edges` array." / PD-02 — graph is rejected when START node is absent.

---

### TC-PD-01-04: Create with description omitted → allowed

**Given:** `CreateParams` with `description = null`, valid graph.  
**When:** `store.create()` is called.  
**Then:** returns a `Definition` (no error); `definition.description == null`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-01 edge case — "`description` omitted: allowed (optional field)."

### TC-PD-02-01: Valid graph (one START, one END, all edges valid) → passes

**Given:** a minimal valid graph: START → USER_TASK → END with connecting edges.  
**When:** `store.create()` is called.  
**Then:** returns a `Definition` with no error.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-02 — "GIVEN a graph with exactly one START, at least one END,
all edges referencing existing nodes, no isolated nodes, no duplicate node IDs, no non-gateway
cycles, and counts within limits, WHEN validated, THEN validation passes."

### TC-PD-02-02: Zero START nodes → HTTP 422, MISSING_START_NODE violation

**Given:** a graph with one USER_TASK and one END but no START node.  
**When:** `store.create()` is called.

`store.lastViolations()` contains code `"MISSING_START_NODE"`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-02 — "GIVEN zero or more than one START node, THEN HTTP 422
identifies the START node violation."

### TC-PD-02-08: Non-gateway cycle → HTTP 422, CYCLE_WITHOUT_GATEWAY violation

**Layer:** integration

### TC-PD-02-09: Cycle through EXCLUSIVE_GATEWAY → passes (allowed)

**Given:** a graph: START → EXCLUSIVE_GATEWAY → USER_TASK → EXCLUSIVE_GATEWAY (back edge) → END.
The cycle passes through the EXCLUSIVE_GATEWAY.  
**When:** `store.create()` is called.  
**Then:** returns a `Definition` (no error). No `"CYCLE_WITHOUT_GATEWAY"` violation.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-02 edge case — "A cycle that passes through a
PARALLEL_GATEWAY or EXCLUSIVE_GATEWAY node: permitted."

---

### TC-PD-02-10: Node count > 500 → HTTP 422, NODE_LIMIT_EXCEEDED violation

**Given:** a graph with 501 nodes (exceeds MAX_NODES = 500).  
**When:** `store.create()` is called.  
**Then:** returns `GraphValidationFailed`;
`store.lastViolations()` contains code `"NODE_LIMIT_EXCEEDED"`.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-02 — "GIVEN > 500 nodes or > 2,000 edges, THEN HTTP 422
identifies the limit exceeded."

---

### TC-PD-02-11: Multiple violations listed (not just the first)

**Given:** a graph that simultaneously has no START node, no END node, and a dangling edge.  
**When:** `store.create()` is called.  
**Then:** returns `GraphValidationFailed`;
`store.lastViolations()` contains **all** of: `"MISSING_START_NODE"`, `"MISSING_END_NODE"`,
and `"DANGLING_EDGE"` — proving that all violations are collected, not just the first.  

**Layer:** integration  
**Acceptance criterion mapped:** PD-02 — "Validation errors MUST list ALL violations found, not
just the first."
