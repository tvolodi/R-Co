# Test Spec: EXP-701 - Sandbox Threat Model Document Gate

**Requirement:** EXP-701 - Define and maintain the sandbox threat model document as a go-live gate for EXP-702 and EXP-703, including required sections, checklist depth, and architecture cross-reference.
**Priority:** MUST
**Test layer:** unit

## Test Cases

### TC-EXP-701-01: threat model document has all 7 required top-level sections
**Given:** the file docs/sandbox_threat_model.md is part of the repository
**When:** the static unit test loads the document with @embedFile and checks required section headers
**Then:** all 7 required section headers are present in the document
**Layer:** unit
**Acceptance criterion mapped:** required document structure is complete and reviewable

### TC-EXP-701-02: go-live gate checklist includes at least 20 checklist items
**Given:** the threat model go-live checklist is defined in docs/sandbox_threat_model.md
**When:** the static unit test counts checklist rows (L-*, W-*, A-*, X-*)
**Then:** the checklist contains at least 20 items
**Layer:** unit
**Acceptance criterion mapped:** go-live gate is sufficiently comprehensive

### TC-EXP-701-03: backend architecture document contains threat-model cross-reference
**Given:** the backend architecture document is docs/BPM_Platform_Backend_Architecture.md
**When:** the static unit test loads the architecture document with @embedFile
**Then:** it contains a cross-reference to docs/sandbox_threat_model.md
**Layer:** unit
**Acceptance criterion mapped:** architecture-to-threat-model traceability is present

### TC-EXP-701-04: all five technical acceptance criteria are explicitly documented
**Given:** EXP-701 acceptance requires coverage of Lua host-API, Wasm host-API, capability gating, limiters, and sandbox-control auth
**When:** the static unit test validates that each criterion has a dedicated section with required keywords
**Then:** all five technical criteria are present and machine-verifiable from the document content
**Layer:** unit
**Acceptance criterion mapped:** technical go-live criteria coverage for automated validation

### TC-EXP-701-05: go-live release status artifact is checked when present
**Given:** release validation writes docs/status/release-exp701-20260614.yaml
**When:** the static unit test checks for this file
**Then:** the test passes if the file exists, and skips (not fails) if absent before release validation
**Layer:** unit
**Acceptance criterion mapped:** automated gate integration with release workflow artifacts

### TC-EXP-701-SIGNOFF: human sign-off attestation (non-automatable)
**Given:** EXP-701 requires reviewed/signed-off status by ARCHITECT + human
**When:** automated tests are executed
**Then:** Human sign-off is required but CANNOT be automated. The test suite verifies all technical acceptance criteria; sign-off is recorded in docs/status/release-exp701-20260614.yaml as a human attestation.
**Layer:** process gate (human)
**Acceptance criterion mapped:** reviewed/signed-off gate state
