**Requirements:** TM-01 (platform-admin tenant list), TM-02 (navigation to onboarding — frontend only), TM-03 (edit tenant mutable fields)

**Implementation files tested:**
- `src/api/routes/identity.zig` — `handleListTenants`, `handlePatchTenant`
- `src/identity/service.zig` — `listTenantsAdmin`, `patchTenant`
- `src/identity/registry.zig` — `listTenants`, `updateTenantDisplayName`, `selectTenantBySlug`
- `web/src/pages/admin/tenants/TenantsPage.tsx`
- `web/src/pages/admin/tenants/EditTenantPage.tsx`
- `web/src/api/tenants.ts`

| Test case | Layer | Requirement | Assertion |
|---|---|---|---|
| TC-TM-01-01 | Route handler | TM-01 | PLATFORM_ADMIN can list tenants — `handleListTenants` returns HTTP 200 with `{items: [...], total: N}` |
| TC-TM-01-02 | Route handler | TM-01 | Non-PLATFORM_ADMIN (`VIEWER`) gets HTTP 403 from `handleListTenants` |
| TC-TM-01-03 | Route handler | TM-01 | Pagination — calling with `limit=2, offset=2` returns the correct slice; `total` matches the full count |

| TC-TM-03-02 | Route handler | TM-03 | PATCH body containing `"slug"` key returns HTTP 422 `immutable_field_update` |
| TC-TM-03-03 | Route handler | TM-03 | PATCH body containing `"idp_realm_id"` key returns HTTP 422 `immutable_field_update` |
| TC-TM-03-04 | Route handler | TM-03 | PATCH on a non-existent slug returns HTTP 404 `tenant_not_found` |

### Fixture strategy

- Each test creates its own tenant(s) with a unique slug derived from the test ID (e.g. `tc-tm-01-01`).
- Pre-cleanup at start and `defer` cleanup at end ensure isolation across repeated runs.
- No static IDs; no shared state between test blocks.
- All tests skip with `error.SkipZigTest` when `BPM_TEST_DB_URL` is absent.

### Fixture strategy

- Uses the existing `admin-user` / `admin-pass` Keycloak credentials for all PLATFORM_ADMIN tests.
- Non-admin tests inject a session with `PROCESS_OPERATOR` roles via `addInitScript` to test frontend role-gating without requiring a separate Keycloak user.
- Screenshots are taken after every significant UI state change for visual verification.
- All E2E verdicts are of the form "screen shows X" — not "no error was thrown".

### Pre-flight

Every test in the `describe` block runs `assertServiceReadiness` in `beforeEach` to fail fast if the backend or Keycloak is unavailable.
