# Test Spec: PD-10 — Definition search

**Requirement:** PD-10 — The platform COULD provide full-text search over definition names and
descriptions, returning ranked results.  
**Priority:** COULD  
**Test layer:** unit (input validation — no DB), integration (Store.search() against real DB)

---

## Shared preconditions

### Unit tests (`tests/unit/pd10_search_unit_test.zig`)

- No database connection required.
- Tests exercise early-exit paths in `handleSearch` that return before any Store method is called.
- Uses `std.testing.allocator`.
- `dummy_store` is left `undefined`; the handler returns before accessing any Store field.

### Integration tests (`tests/integration/pd10_search_test.zig`)

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()`).
- Each DB-dependent test creates its own rows via `DefinitionStore.create()` using deterministic
  name prefixes (`"TC-PD-10-NN …"`) and cleans up via `cleanupByName()` on defer.
- Creator UUID is `"00000000-0000-0000-0000-000000000099"` (no FK constraint on `created_by`).
- Validation-only tests (TC-PD-10-05, TC-PD-10-06, TC-PD-10-11) run without a DB and always
  pass without skipping.

### TC-PD-10-01: Exact name match returns rank 3.0

**Given:** A definition with name `"TC-PD-10-01 Onboarding Flow"` exists in `process_definitions`.  
**When:** `Store.search(alloc, SearchOptions{.query="TC-PD-10-01 Onboarding Flow", .limit=20, .offset=0})` is called.  
**Then:**  
- Returns `[]SearchResult` without error.  
- At least one result; `results[i].definition.name == "TC-PD-10-01 Onboarding Flow"`.  
- That result has `rank == 3.0` (exact match: `name ILIKE $1`).  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — GIVEN a search query, WHEN `GET /definitions/search?q=` is called,
THEN HTTP 200 + ranked list; results ordered by relevance (highest first).

---

### TC-PD-10-02: Partial name match returns rank 2.0

**Given:** A definition with name `"TC-PD-10-02 Invoice Processing Pipeline"` exists.  
**When:** `Store.search(alloc, SearchOptions{.query="Invoice", .limit=20, .offset=0})` is called.  
**Then:**  
- Returns `[]SearchResult` without error.  
- At least one result whose `definition.name` contains `"Invoice"`.  
- That result has `rank == 2.0` (partial name match: `name ILIKE '%Invoice%'`; `"Invoice"` ≠ full name).  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — search SHOULD support partial word matching; results ranked.

### TC-PD-10-03: Description-only match returns rank 1.0

**Given:** A definition with name `"TC-PD-10-03 Approval Process"` and description
`"quarterly budget review"` exists. The name does not contain `"quarterly budget review"`.  
**When:** `Store.search(alloc, SearchOptions{.query="quarterly budget review", .limit=20, .offset=0})`
is called.  
**Then:**  
- Returns `[]SearchResult` without error.  
- At least one result; `results[i].definition.description` contains `"quarterly budget review"`.  
- That result has `rank == 1.0` (description-only match: ELSE branch in CASE expression).  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — description field is searched; rank 1.0 for description-only.

### TC-PD-10-04: No matching definitions returns empty slice

is called.  
**Then:** Returns `[]SearchResult` of length 0 without error (no `DefinitionNotFound` error).  
**Layer:** integration  
**DB required:** Yes

### TC-PD-10-05: Empty query string returns QueryEmpty

**Given:** An empty query string `""`.  
**When:** `Store.search(alloc, SearchOptions{.query="", .limit=20, .offset=0})` is called.  
**Then:** Returns `DefinitionError.QueryEmpty`. No DB access occurs.  
**Layer:** unit (via `handleSearch`) + integration (via `Store.search()` directly)  
**DB required:** No  
**Acceptance criterion mapped:** PD-10 — empty query (`q=`) MUST be rejected with HTTP 422.

### TC-PD-10-06: Query longer than 512 characters returns QueryTooLong

**Given:** A query string of 513 characters (all `'a'`).  
**When:** `Store.search(alloc, SearchOptions{.query=<513×'a'>, .limit=20, .offset=0})` is called.  
**Then:** Returns `DefinitionError.QueryTooLong`. No DB access occurs.  
**Layer:** unit (via `handleSearch`) + integration (via `Store.search()` directly)  
**DB required:** No  
**Acceptance criterion mapped:** PD-10 — very long query (> 512 characters) rejected with HTTP 422.

### TC-PD-10-08: Name match ordered before description-only match

**Given:** Two definitions exist:  
  - Name `"TC-PD-10-08 purchasing workflow"` (name contains `"purchasing"`, description does not).  
  - Name `"TC-PD-10-08 unrelated process"`, description `"purchasing approval flow"` (name does not
    contain `"purchasing"`).  
**When:** `Store.search(alloc, SearchOptions{.query="purchasing", .limit=20, .offset=0})` is called.  
**Then:**  
- Returns exactly 2 results.  
- `results[0]` is the name-matching definition (rank ≥ 2.0).  
- `results[1]` is the description-only-matching definition (rank 1.0).  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — results MUST be ordered by relevance (highest-scoring first).

### TC-PD-10-09: Pagination with limit and offset

**Given:** Three definitions with names `"TC-PD-10-09 paginate-A"`, `"TC-PD-10-09 paginate-B"`,
`"TC-PD-10-09 paginate-C"` exist.  
**When:**  
1. `Store.search(alloc, SearchOptions{.query="TC-PD-10-09", .limit=2, .offset=0})` is called.  
2. `Store.search(alloc, SearchOptions{.query="TC-PD-10-09", .limit=2, .offset=2})` is called.  
**Then:**  
- Call 1 returns exactly 2 results.  
- Call 2 returns exactly 1 result.  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — pagination MUST be supported per API-06.

### TC-PD-10-10: SQL-special characters handled safely (no injection)

**Given:** A query string containing SQL-special characters: `"'; DROP TABLE process_definitions; --"`.  
**When:** `Store.search(alloc, SearchOptions{.query="'; DROP TABLE process_definitions; --", .limit=20, .offset=0})`
is called.  
**Then:**  
- Returns without error (no panic, no SQL error, no injection).  
- Returns 0 results.  
- `process_definitions` table remains intact (verified by a subsequent `count` query or by the
  fact that earlier tests still work).  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — query containing SQL-special characters handled safely.

---

### TC-PD-10-11: Absent q parameter returns HTTP 422 query_empty

**Given:** `handleSearch` is called with `SearchQueryParams{.q=null, .limit=null, .offset=null}`.
At the `Store` level this is equivalent to an empty query; both map to `QueryEmpty`.  
**When:** `handleSearch(&dummy_store, alloc, params)` is called with `params.q = null`.  
**Then:** `result.status_code == 422` and body contains `"query_empty"`.
No Store method is called.  
**Layer:** unit (via `handleSearch`) + integration (Store-level — same as TC-PD-10-05)  
**DB required:** No  
**Acceptance criterion mapped:** PD-10 — absent `q=` parameter MUST be rejected with HTTP 422.

---

### TC-PD-10-12: Search returns definitions across all statuses

**Given:** Four definitions with the name prefix `"TC-PD-10-12 "` exist with statuses DRAFT,
ACTIVE, DEPRECATED, and ARCHIVED (forced via SQL UPDATE after creation).  
**When:** `Store.search(alloc, SearchOptions{.query="TC-PD-10-12", .limit=20, .offset=0})` is called.  
**Then:**  
- Returns exactly 4 results (one per status).  
- The result set contains a definition with each of the four statuses.  
**Layer:** integration  
**DB required:** Yes  
**Acceptance criterion mapped:** PD-10 — no status filter in the search SQL; all statuses are included.
