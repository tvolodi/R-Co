# Test Spec: ISS-602 -- CEL-to-expr Differential Test Corpus (Cutover Gate)

**Requirement:** ISS-602 -- Differential harness evaluates a corpus of real/stored gateway conditions on both `vendor/cel` and `src/expr/` and asserts identical boolean results. Divergences catalogued with condition text, CEL result, expr result, and diff detail. Cutover blocked until corpus is 100% green. No production module imports `src/expr/` on the engine path until this gate passes.  
**Priority:** MUST  
**Test layer:** unit (no DB), integration (corpus JSON fixtures)

## Test Cases

### TC-ISS-602-01: Differential harness -- evaluate all conditions on both CEL and expr, assert identical boolean results
**Given:** A corpus JSON file at `tests/differential/corpus/conditions_v1.json` containing N gateway conditions with condition_text, context variables, and expected_result.  
**When:** The differential test harness loads the corpus, evaluates each condition with both `vendor/cel/cel.evaluate()` and `src/expr/mod.evaluate()`, and compares boolean results.  
**Then:** Every condition produces the same boolean result on both evaluators (`match = true`). The total matched count equals the total condition count. The test exits with `test PASS`.  
**Layer:** integration (embedFile corpus)  
**Acceptance criterion mapped:** "Each condition is evaluated on both `vendor/cel` and `src/expr/` and boolean results are asserted identical."

### TC-ISS-602-02: Divergence cataloguing -- when conditions diverge, divergence is properly catalogued
**Given:** A corpus entry where CEL and expr produce different boolean results (e.g., CEL returns `true`, expr returns `false` due to type coercion difference).  
**When:** `evaluateDifferential(entry)` is called.  
**Then:** A `DiffResult` is returned with `match = false`, both `cel_result` and `expr_result` populated, `diff_detail` containing a human-readable description of the semantic difference (e.g., "CEL: true, expr: false. Difference: type coercion mismatch"), and the divergence is counted in the aggregate report under `diverged`.  
**Layer:** unit  
**Acceptance criterion mapped:** "Divergences catalogued with condition text, CEL result, expr result, and diff detail."

### TC-ISS-602-03: Gate -- verify no production module on engine path imports src/expr/
**Given:** The source tree of `src/engine/transition.zig`.  
**When:** A text search for `@import("../../expr/")` or `@import("../expr/")` is performed against `src/engine/transition.zig`.  
**Then:** No import of `src/expr/` is found. The current production evaluator for gateway conditions remains `vendor/cel/cel.zig`.  
**Layer:** unit (static analysis)  
**Acceptance criterion mapped:** "Cutover gate enforced: no production module imports `src/expr/` on the engine path until corpus is 100% green."

### TC-ISS-602-04: Corpus loading -- initial corpus loads from process definitions
**Given:** The corpus file `tests/differential/corpus/conditions_v1.json` exists in the repository.  
**When:** The file is parsed as JSON.  
**Then:** It is a valid JSON array of corpus entry objects. Each entry has all required fields: `condition_id`, `source_definition_id`, `source_definition_version`, `source_gateway_node_id`, `condition_text`, `context` (non-empty object), and `expected_result` (boolean). The corpus contains at least one condition.  
**Layer:** integration  
**Acceptance criterion mapped:** "Corpus version-controlled at `tests/differential/corpus/conditions_v1.json`."

### TC-ISS-602-05: Mechanical translator -- CEL-to-expr translation within grammar intersection
**Given:** CEL condition text `"variables.order_total > 1000 && variables.is_urgent == true"`.  
**When:** `translateCelToExpr(cel_expression)` is called.  
**Then:** The function returns `"order_total > 1000 and is_urgent == true"` -- stripping the `variables.` prefix and converting `&&` to `and`.  
**Layer:** unit  
**Acceptance criterion mapped:** "Mechanical translator handles the CEL/expr grammar intersection."

### TC-ISS-602-06: Translator unsupported features -- CEL features outside the grammar intersection return null
**Given:** CEL condition text `"variables.items.size() > 0"` (CEL macro/function not in the expr whitelist).  
**When:** `translateCelToExpr(cel_expression)` is called.  
**Then:** The function returns null (unsupported feature). The harness records this as a divergence with `diff_detail` explaining the unsupported feature.  
**Layer:** unit  
**Acceptance criterion mapped:** "Unsupported features recorded as divergences."

### TC-ISS-602-07: Context conversion -- JSON values correctly converted to expr types
**Given:** A `std.json.ObjectMap` with integer, float, string, boolean, and null values.  
**When:** `jsonValueToExprValue()` is called for each value.  
**Then:** Integer JSON values map to `expr.Value.int_val`, float to `expr.Value.float_val`, string to `expr.Value.str_val`, boolean to `expr.Value.bool_val`, null to `expr.Value.null_val`.  
**Layer:** unit  
**Acceptance criterion mapped:** Context conversion between CEL (JSON) and expr (typed Value) context formats.

### TC-ISS-602-08: Expected result verification -- corpus expected_result matches CEL evaluation
**Given:** Each entry in the corpus with `condition_text` and `context`.  
**When:** `cel.evaluate(condition_text, context)` is called.  
**Then:** The boolean result matches `entry.expected_result`. This verifies the corpus baseline is correct (CEL is the current production evaluator).  
**Layer:** integration  
**Acceptance criterion mapped:** Verifies corpus correctness -- the expected_result field is accurate against the CEL baseline.
