# Test Spec: ES-01–ES-08 — Event Store (Append, Order, Idempotency, Global Stream, Registry, Point-in-Time, Retention, Metadata)

---

## ES-01 — Append event

**Requirement:** ES-01 — The platform SHALL append a typed, immutable event record to the event log for a given process instance. Each event carries: `event_id` (UUID v4), `instance_id`, `event_type`, `payload` (JSON), `actor_id`, and `created_at` (UTC timestamp with microsecond precision).  
**Priority:** MUST  
**Test layer:** unit, integration

### TC-ES-01-01: Valid append returns AppendResult with is_duplicate=false and persisted record

**Given:** An active process instance with a valid `instance_id`; an event type registered in the registry; a valid JSON object payload; a non-nil `actor_id`; a unique `idempotency_key`  
**When:** `Store.append()` is called with all valid parameters  
**Then:** `AppendResult.is_duplicate` is `false`; `AppendResult.record.event_id` is a non-zero UUID; `AppendResult.record.created_at` is a UTC microsecond timestamp greater than 0; the event row is readable via `Store.read()`  
**Layer:** integration  
**Acceptance criterion mapped:** Valid append → HTTP 201 with persisted event record including platform-assigned event_id and created_at

### TC-ES-01-02: Append to non-existent instance returns InstanceNotFound

**Given:** A `Store` backed by a pool where `instance_projections` contains no row for the given `instance_id`  
**When:** `Store.append()` is called with a valid `instance_id` that does not exist  
**Then:** `Store.append()` returns `StoreError.InstanceNotFound`; no event row is inserted  
**Layer:** unit  
**Acceptance criterion mapped:** instance_id MUST reference an existing process instance; absent → HTTP 404

### TC-ES-01-03: Append to COMPLETED instance returns InstanceTerminated

**Given:** An instance in `instance_projections` with `status = "COMPLETED"`  
**When:** `Store.append()` is called for that instance  
**Then:** `Store.append()` returns `StoreError.InstanceTerminated`; no event row is inserted  
**Layer:** unit  
**Acceptance criterion mapped:** Appending to a COMPLETED instance → HTTP 409

### TC-ES-01-04: Append to CANCELLED instance returns InstanceTerminated

**Given:** An instance in `instance_projections` with `status = "CANCELLED"`  
**When:** `Store.append()` is called for that instance  
**Then:** `Store.append()` returns `StoreError.InstanceTerminated`; no event row is inserted  
**Layer:** unit  
**Acceptance criterion mapped:** Appending to a CANCELLED instance → HTTP 409

### TC-ES-01-05: Append with nil actor_id returns ActorIdMissing

**Given:** A valid append request where `actor_id` is the all-zeros UUID (nil)  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.ActorIdMissing`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** actor_id MUST be non-empty; null/absent → HTTP 422

### TC-ES-01-06: Append with JSON array payload returns PayloadInvalid

**Given:** A valid append request where `payload = "[]"` (JSON array)  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.PayloadInvalid`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** payload MUST be a valid JSON object; array → HTTP 422

## ES-02 — Ordered read

**Requirement:** ES-02 — Events for an instance SHALL be retrievable in strict append order (sequence number). Concurrent reads MUST NOT return events out of sequence.  
**Priority:** MUST  
**Test layer:** integration

### TC-ES-02-01: Two sequential appends to same instance receive sequence_numbers 1 and 2

**Given:** An active instance with no events  
**When:** Two `Store.append()` calls are made to the same `instance_id` in sequence  
**Then:** The first returned `EventRecord.sequence_number` is 1; the second is 2; both values are distinct and monotonically increasing  
**Layer:** integration  
**Acceptance criterion mapped:** sequence_number is monotonically increasing per instance; no gaps in committed sequence

### TC-ES-02-02: Store.read returns events sorted by ascending sequence_number

**Given:** An active instance with 3 persisted events (sequence_numbers 1, 2, 3)  
**When:** `Store.read()` is called with no `ReadOpts` filters  
**Then:** The returned slice has length 3; `result[0].sequence_number == 1`; `result[1].sequence_number == 2`; `result[2].sequence_number == 3`  
**Layer:** integration  
**Acceptance criterion mapped:** Events retrieved in strict ascending sequence order with no gaps

## ES-03 — Event idempotency

**Requirement:** ES-03 — Each event append SHALL include a caller-supplied idempotency key. The key is global in scope. Duplicate submissions with the same key MUST be silently deduplicated and return the original event record.  
**Priority:** MUST  
**Test layer:** unit, integration

### TC-ES-03-01: Duplicate idempotency_key returns original event with is_duplicate=true

**Given:** An event previously appended with `idempotency_key = "key-001"`  
**When:** `Store.append()` is called again with the same `idempotency_key = "key-001"` (any payload, any instance)  
**Then:** `AppendResult.is_duplicate` is `true`; `AppendResult.record.event_id` equals the event_id from the original append; no new event row is inserted  
**Layer:** integration  
**Acceptance criterion mapped:** Duplicate key → HTTP 200 with original event; no new event inserted

### TC-ES-03-02: Empty idempotency_key returns IdempotencyKeyMissing

**Given:** A valid append request where `idempotency_key = ""`  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.IdempotencyKeyMissing`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** Missing or empty idempotency key → HTTP 422

### TC-ES-03-03: idempotency_key of 256 characters returns IdempotencyKeyTooLong

**Given:** A valid append request where `idempotency_key` is a string of exactly 256 characters  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.IdempotencyKeyTooLong`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** Keys longer than 255 characters → HTTP 422

## ES-04 — Global event stream

**Requirement:** ES-04 — The platform SHALL expose a global ordered stream of all events across all instances, usable for projections and read-model rebuilding.  
**Priority:** MUST  
**Test layer:** integration

### TC-ES-04-01: readGlobal returns events in ascending global_seq order

**Given:** Events appended across two different instances (interleaved appends)  
**When:** `Store.readGlobal()` is called with `after_global_seq = null`  
**Then:** All appended events are present; each `EventRecord.global_seq` is strictly greater than the previous entry's `global_seq`; no duplicates  
**Layer:** integration  
**Acceptance criterion mapped:** Global stream ordered by monotonically increasing global_seq

### TC-ES-04-02: readGlobal with after_global_seq cursor returns only events after that position

**Given:** 5 events persisted with `global_seq` values 1–5  
**When:** `Store.readGlobal()` is called with `after_global_seq = 3`  
**Then:** The result contains exactly 2 events with `global_seq` 4 and 5; events with `global_seq` ≤ 3 are absent  
**Layer:** integration  
**Acceptance criterion mapped:** Cursor-based pagination: resume from any position without re-reading earlier events

## ES-05 — Event type registry

**Requirement:** ES-05 — All event types SHALL be registered with a name, schema version, and JSON Schema. Appending an event with an unregistered or schema-invalid payload MUST be rejected with HTTP 422 and a structured error listing all validation failures.  
**Priority:** MUST  
**Test layer:** unit, integration

### TC-ES-05-01: Append with unregistered event_type returns UnknownEventType

**Given:** A `Store` with a `Registry` that has no entry for event_type `"UNKNOWN_TYPE"`  
**When:** `Store.append()` is called with `event_type = "UNKNOWN_TYPE"`  
**Then:** `Store.append()` returns `StoreError.UnknownEventType`; no event row is inserted; `Registry.validatePayload()` was called before any DB write  
**Layer:** unit  
**Acceptance criterion mapped:** event_type not registered → HTTP 422 identifying the unknown type

### TC-ES-05-02: Append with payload failing registered schema returns PayloadSchemaInvalid

**Given:** An event type `"TASK_COMPLETED"` registered with a schema requiring a `"task_id"` field; a payload `"{}"` that omits the required field  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.PayloadSchemaInvalid`; no event row is inserted  
**Layer:** unit  
**Acceptance criterion mapped:** Schema-invalid payload → HTTP 422 with per-field validation failures

### TC-ES-05-03: registerType with invalid JSON Schema document returns InvalidJsonSchema

**Given:** A `RegisterParams` where `json_schema = "not-a-json-object"`  
**When:** `Registry.registerType()` is called  
**Then:** `Registry.registerType()` returns `RegistryError.InvalidJsonSchema`; no row is inserted into `event_type_registry`  
**Layer:** unit  
**Acceptance criterion mapped:** Invalid schema document → HTTP 422

### TC-ES-05-04: registerType with duplicate name+version returns DuplicateEventTypeVersion

**Given:** An event type `"TASK_COMPLETED"` at `schema_version = 1` already registered  
**When:** `Registry.registerType()` is called with the same `name = "TASK_COMPLETED"` and `schema_version = 1`  
**Then:** `Registry.registerType()` returns `RegistryError.DuplicateEventTypeVersion`; no new row is inserted  
**Layer:** unit  
**Acceptance criterion mapped:** Duplicate name+version combination → HTTP 409

## ES-06 — Point-in-time query

**Requirement:** ES-06 — Callers SHALL be able to request the event list for an instance up to a specific sequence number or timestamp, enabling state reconstruction at any point in history.  
**Priority:** MUST  
**Test layer:** integration

### TC-ES-06-01: pointInTime with before timestamp filters out events created after that timestamp

**Given:** An instance with 3 events; events 1 and 2 have `created_at = T1`; event 3 has `created_at = T2` where `T2 > T1`  
**When:** `Store.pointInTime()` is called with `before = T1`  
**Then:** The result contains exactly 2 events (sequence_numbers 1 and 2); event 3 is absent; both returned events have `created_at <= T1`  
**Layer:** integration  
**Acceptance criterion mapped:** up_to_timestamp filter returns only events with created_at ≤ T

### TC-ES-06-02: read with up_to_sequence returns exactly events 1..K

**Given:** An instance with 5 persisted events  
**When:** `Store.read()` is called with `ReadOpts{ .up_to_sequence = 3, .up_to_timestamp = null }`  
**Then:** The result contains exactly 3 events with `sequence_number` 1, 2, 3; events with `sequence_number` > 3 are absent  
**Layer:** integration  
**Acceptance criterion mapped:** up_to_sequence = K returns exactly events 1..K in ascending order

## ES-07 — Retention policy

**Requirement:** ES-07 — The platform SHALL support configurable event retention policies per event type. Expired events SHALL be moved to a dedicated `events_archive` table (same schema), not deleted.  
**Priority:** SHOULD  
**Test layer:** integration

### TC-ES-07-01: archive moves events past retention period to events_archive

**Given:** An `events` table containing an event of type `"TASK_COMPLETED"` with `created_at` older than the configured retention window  
**When:** `Store.archive()` is called with a `retention_days` value that covers the event's age  
**Then:** The event row is no longer present in `events`; the same row (same `event_id`) is present in `events_archive`; no data fields differ between original and archived row  
**Layer:** integration  
**Acceptance criterion mapped:** Events of type T with created_at < NOW() - N days moved atomically from events to events_archive

### TC-ES-07-02: archive returns count of moved rows

**Given:** An `events` table with exactly 3 expired events and 2 non-expired events  
**When:** `Store.archive()` is called  
**Then:** `Store.archive()` returns exactly 3; the 2 non-expired events remain in `events`  
**Layer:** integration  
**Acceptance criterion mapped:** Archival moves correct events; non-expired events are untouched

## ES-08 — Event metadata

**Requirement:** ES-08 — Each event SHALL carry an optional free-form metadata map (string → string) for tracing, correlation IDs, and source tagging without polluting the business payload.  
**Priority:** SHOULD  
**Test layer:** unit, integration

### TC-ES-08-01: Append with metadata key longer than 128 characters returns MetadataInvalid

**Given:** An append request with a `metadata` entry whose key is a string of 129 characters  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.MetadataInvalid`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** metadata keys MUST be ≤ 128 characters; violation → HTTP 422

### TC-ES-08-02: Append with metadata value longer than 1024 characters returns MetadataInvalid

**Given:** An append request with a `metadata` entry whose value is a string of 1025 characters  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.MetadataInvalid`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** metadata values MUST be ≤ 1024 characters; violation → HTTP 422

### TC-ES-08-03: Append with more than 50 metadata entries returns MetadataInvalid

**Given:** An append request with a `metadata` JSON object containing 51 entries  
**When:** `Store.append()` is called  
**Then:** `Store.append()` returns `StoreError.MetadataInvalid`; no DB write occurs  
**Layer:** unit  
**Acceptance criterion mapped:** Total metadata entries per event MUST NOT exceed 50; violation → HTTP 422

### TC-ES-08-04: Absent metadata field defaults to empty object in returned record

**Given:** An append request with `metadata = null`  
**When:** `Store.append()` completes successfully  
**Then:** `AppendResult.record.metadata` equals `"{}"` (the empty JSON object); the stored and returned value is `{}` not null  
**Layer:** integration  
**Acceptance criterion mapped:** No metadata field → defaults to {} and is returned as such
