# Test Spec: PD-08 — Definition snapshot

**Requirement:** PD-08 — Definition snapshot (MUST) — The platform SHALL capture an immutable
snapshot of a process definition's graph at the moment a process instance is created.  The snapshot
SHALL be bound to the instance by `instance_id` and persist independently of any subsequent changes
or deletion of the source definition.

**Priority:** MUST
**Test layer:** unit (stubs catalogued; all require DB), integration (`SnapshotStore.create()`,
`SnapshotStore.getByInstanceId()`)

---

## Shared preconditions

### Unit tests (`tests/unit/test_snapshot.zig`)

- All `SnapshotStore` methods require a live database connection through `Pool.acquire()`.  There
  are no pure-function paths in `snapshot.zig` that can be exercised without a real DB.
- All test blocks in `test_snapshot.zig` return `error.SkipZigTest` and are catalogued for
  requirement traceability only.  They MUST be promoted to full integration tests before PD-08 can
  advance to `TESTED` status.
- The integration layer below is the primary verification vehicle for PD-08.

### Integration tests (`tests/integration/test_snapshot_integration.zig`)

- A real PostgreSQL database is reachable at `BPM_TEST_DB_URL`.
- All migrations have been applied (via `TestHarness.init()` at the start of each test).
- A `bpm.pool.Pool` is created per test with `pool_size = 5`.
- A `bpm.snapshot.SnapshotStore` is constructed as a struct literal: `SnapshotStore{ .pool = &pool }`.
- Definitions are inserted via `bpm.definition.Store.create()` using test names prefixed with
  `"TC-PD-08-"` so cleanup via `cleanupByName()` covers all test rows.
- Instance UUIDs are deterministic fixed values (`"00000000-0000-0000-0000-0000000008XX"`).
- Cleanup order: snapshot rows are deleted before definition rows to respect FK constraints.
- `std.testing.allocator` is used throughout; all `Snapshot` values are freed with `freeSnapshot()`.

### TC-PD-08-01: Create snapshot — happy path

**Given:** A definition exists in `process_definitions` with a known `definition_id`, `name`, and
`version`.  A fresh `instance_id` UUID has no corresponding row in
`instance_definition_snapshots`.
**When:** `SnapshotStore.create(allocator, instance_id, definition_id)` is called.
**Then:**
- Returns `Snapshot` without error.
- `snapshot.definition_id` equals `definition_id`.
- `snapshot.definition_name` equals the definition's `name`.
- `snapshot.definition_ver` equals the definition's `version`.
- A row now exists in `instance_definition_snapshots` for `instance_id`.
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "The platform SHALL capture a snapshot at instance-creation
time containing the definition's `definition_id`, `name`, and `version`."

---

### TC-PD-08-02: Snapshot is independent of subsequent definition update

**Given:** A snapshot was created for `instance_id = A` from definition `D` whose graph has
`N` nodes.
**When:** The definition `D`'s `graph` column is updated (via a direct SQL UPDATE in test setup) to
a new graph with a different node count `M` (M ≠ N), and then
`SnapshotStore.getByInstanceId(allocator, instance_id_A)` is called.
**Then:** The returned snapshot's `graph.nodes.len` equals `N` (the original node count, not `M`).
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "The snapshot SHALL persist independently of any subsequent
changes to the source definition."

---

### TC-PD-08-03: Duplicate `instance_id` returns `SnapshotAlreadyExists`

**Given:** A snapshot for `instance_id = X` already exists in `instance_definition_snapshots`.
**When:** `SnapshotStore.create(allocator, instance_id_X, definition_id)` is called again with the
same `instance_id_X`.
**Then:** Returns `SnapshotError.SnapshotAlreadyExists` (maps to HTTP 409).
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "A duplicate insert for the same `instance_id` SHALL be
rejected.  The `ON CONFLICT DO NOTHING` constraint enforces idempotency at the DB level."

---

### TC-PD-08-04: Unknown `definition_id` returns `DefinitionNotFound`

**Given:** `definition_id = U` does not exist in `process_definitions`.
**When:** `SnapshotStore.create(allocator, fresh_instance_id, U)` is called.
**Then:** Returns `SnapshotError.DefinitionNotFound` (maps to HTTP 404).
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "If the referenced definition does not exist, the snapshot
SHALL be rejected with HTTP 404."

---

### TC-PD-08-05: `getByInstanceId` with no snapshot returns `DefinitionNotFound`

**Given:** No row exists in `instance_definition_snapshots` for `instance_id = Y`.
**When:** `SnapshotStore.getByInstanceId(allocator, instance_id_Y)` is called.
**Then:** Returns `SnapshotError.DefinitionNotFound` (repurposed as "snapshot not found").
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "`getByInstanceId` returns not-found when no snapshot row
exists for the given `instance_id`."

---

### TC-PD-08-06: Snapshot includes all graph fields

**Given:** A definition with a graph containing:
- A `START` node
- A `HUMAN_TASK` node with `attributes` encoding a `role` field
- An `EXCLUSIVE_GATEWAY` node
- Two `END` nodes
- A non-default outgoing edge from the gateway carrying a CEL `condition` expression (`"approved == true"`)
- A default outgoing edge from the gateway with `is_default = true` and no condition

**When:** `SnapshotStore.create()` is called (snapshot row inserted), then
`SnapshotStore.getByInstanceId()` is called (snapshot row retrieved and parsed).
**Then:** The round-tripped graph satisfies all of the following:
- `nodes.len` equals the original node count.
- Node types (START, HUMAN_TASK, EXCLUSIVE_GATEWAY, END) are preserved.
- Edge `condition` value (`"approved == true"`) is preserved on the non-default edge.
- `is_default = true` is preserved on the default edge.
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "The graph stored in the snapshot MUST include all nodes,
edges, conditions, and `is_default` flags."

### TC-PD-08-07: Two instances from same definition have independent snapshots

**Given:** Two instances (`instance_id_A` and `instance_id_B`) both snapshot the same definition.
Instance A's snapshot is created first (graph version G1 with `Na` nodes).  The definition's
`graph` column is then updated directly in the DB to G2 (with `Nb` nodes, `Nb ≠ Na`).  Instance
B's snapshot is created after the update.
**When:**
- `SnapshotStore.getByInstanceId(allocator, instance_id_A)` is called.
- `SnapshotStore.getByInstanceId(allocator, instance_id_B)` is called.
**Then:**
- Instance A's snapshot has `graph.nodes.len == Na` (graph G1, before the update).
- Instance B's snapshot has `graph.nodes.len == Nb` (graph G2, after the update).
**Layer:** integration
**Acceptance criterion mapped:** PD-08 — "Each instance holds its own independent snapshot; changes
to a definition after one instance is started do not affect that instance's snapshot."

## Edge Cases

- **Pool exhausted during `create`:** `SnapshotStore.create()` returns `SnapshotError.PoolExhausted`
  when `Pool.acquire()` fails with `ExhaustedPool`.  This path requires pool exhaustion simulation
  and is catalogued in the DB-02 pool test suite (DB-02 tests cover `ExhaustedPool` propagation).

- **Definition deleted after snapshot exists:** Because `instance_definition_snapshots.definition_id`
  carries no `ON DELETE CASCADE`, deleting a `process_definitions` row does NOT cascade to
  snapshots.  Existing snapshot rows retain their captured graph and remain readable via
  `getByInstanceId()`.  This is by design (PD-08 immutability guarantee).

- **Transaction commit failure:** `SnapshotStore.create()` returns `SnapshotError.TransactionFailed`
  on `BEGIN`, query, or `COMMIT` errors.  The `errdefer conn.rollback()` guard ensures no partial
  state is written.

- **Concurrent duplicate `create` race:** Two concurrent EE-01 calls for the same `instance_id`
  compete.  The `ON CONFLICT (instance_id) DO NOTHING` constraint ensures only one INSERT wins;
  the loser receives `SnapshotError.SnapshotAlreadyExists`.  EE-01 MUST treat this as idempotent
  success (the snapshot already exists with the correct graph).
