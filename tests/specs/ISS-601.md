# Test Spec: ISS-601 -- State Snapshots for Large-Instance Reconstruction

**Requirement:** ISS-601 -- Periodic per-instance state snapshot; reconstruction folds events since the latest snapshot instead of full replay. Replay joins `event_payloads_overflow` to reconstruct full payloads. NFR-04 (<=5s for 10k events) verified by benchmark. Snapshot table with `(instance_id, snapshot_seq)` PK. Snapshot interval: every 1000 events, and on instance completion.  
**Priority:** MUST  
**Test layer:** integration (Zig + real PostgreSQL), benchmark

## Test Cases

### TC-ISS-601-01: Full replay fallback -- instance without snapshots reconstructs correctly
**Given:** A process instance with N events (e.g., 5 events: instance_started + task_completed sequence) and NO snapshot rows in `instance_state_snapshots`.  
**When:** `reconstructInstanceWithSnapshot(instance_id, write_back=false)` is called.  
**Then:** The function falls back to full replay (existing `reconstructInstance` path), returns an `InstanceState` matching the expected final state (tokens, variables, status), and the result is identical to calling `reconstructInstance` directly on the same instance.  
**Layer:** integration  
**Acceptance criterion mapped:** "Existing `reconstructInstance` and `reconstructInstancePointInTime` preserved unchanged as fallback paths."

### TC-ISS-601-02: Snapshot-based reconstruction -- instance with snapshots reconstructs correctly via delta path
**Given:** A process instance with 50 events and a snapshot inserted at sequence number 25 with the correct state_blob representing the state after event 25.  
**When:** `reconstructInstanceWithSnapshot(instance_id, write_back=false)` is called.  
**Then:** The function loads the snapshot at seq 25, replays events 26..50 through `transition()`, and returns an `InstanceState` matching the expected final state (identical to full replay of all 50 events).  
**Layer:** integration  
**Acceptance criterion mapped:** "Periodic per-instance state snapshot; reconstruction folds events since the latest snapshot."

### TC-ISS-601-03: Snapshot creation -- snapshot is created after interval events
**Given:** A process instance with `DEFAULT_SNAPSHOT_INTERVAL` (1000) events committed.  
**When:** `SnapshotWriter.maybeTakeSnapshot(state, current_seq=1000, status=ACTIVE, interval=1000)` is called.  
**Then:** A row is inserted into `instance_state_snapshots` with `instance_id`, `snapshot_seq=1000`, and a non-null `state_blob` containing the full JSON serialisation of the InstanceState.  
**Layer:** integration  
**Acceptance criterion mapped:** "Snapshot interval: every 1000 events."

### TC-ISS-601-04: Snapshot on completion -- terminal instance gets a final snapshot
**Given:** A process instance whose status transitions to COMPLETED at sequence number 30.  
**When:** `SnapshotWriter.maybeTakeSnapshot(state, current_seq=30, status=COMPLETED, interval=1000)` is called.  
**Then:** A snapshot is taken unconditionally (completion path), with `snapshot_seq=30` and `status="COMPLETED"` serialised in `state_blob`, regardless of the interval distance from the previous snapshot.  
**Layer:** integration  
**Acceptance criterion mapped:** "Snapshot interval: ... and on instance completion (COMPLETED, CANCELLED, ERROR)."

### TC-ISS-601-05: Overflow payload join -- reconstruction correctly joins event_payloads_overflow
**Given:** A process instance with an event whose payload exceeds 4KB (stored in `event_payloads_overflow` with `$ref: overflow` in `events.payload`). A snapshot exists at a sequence number before the overflow event.  
**When:** `reconstructInstanceWithSnapshot(instance_id)` replays the overflow event as part of the delta.  
**Then:** The full payload is reconstructed via `COALESCE(epo.payload, e.payload)` join, the event is successfully mapped to `TransitionEvent`, and the final state is correct.  
**Layer:** integration  
**Acceptance criterion mapped:** "Replay joins `event_payloads_overflow` to reconstruct full payloads."

### TC-ISS-601-06: NFR-04 benchmark -- 10k event replay completes within 5 seconds
**Given:** A process instance with 10,000 events (no snapshots -- full replay path).  
**When:** `reconstructInstance(instance_id)` is called and wall-clock time is measured.  
**Then:** The replay completes in under 5 seconds (NFR-04 target).  
**Layer:** benchmark (zig build bench)  
**Acceptance criterion mapped:** "NFR-04 (<=5s for 10k events) verified by benchmark."

### TC-ISS-601-07: Idempotent snapshot -- duplicate snapshot is no-op
**Given:** A snapshot already exists at `(instance_id, snapshot_seq=50)`.  
**When:** `SnapshotWriter.takeSnapshot(state, snapshot_seq=50)` is called again.  
**Then:** The INSERT uses `ON CONFLICT DO NOTHING` and no error is returned. The row count in `instance_state_snapshots` for this `(instance_id, snapshot_seq)` remains 1.  
**Layer:** integration  
**Acceptance criterion mapped:** "Snapshot idempotency. Taking a snapshot at the same (instance_id, snapshot_seq) twice is a no-op."

### TC-ISS-601-08: Multi-boundary snapshots -- snapshots at multiple interval boundaries
**Given:** A process instance with 2,500 events.  
**When:** Snapshots are taken at sequence numbers 1000 and 2000. `reconstructInstanceWithSnapshot` is called.  
**Then:** The function uses the latest snapshot (seq 2000), replays events 2001..2500, and produces correct final state. The snapshot at seq 1000 remains in the table (no pruning).  
**Layer:** integration  
**Acceptance criterion mapped:** "Periodic per-instance state snapshot" -- verifies multiple boundaries.

### TC-ISS-601-09: Corrupt snapshot fallback -- invalid state_blob triggers full replay
**Given:** A row exists in `instance_state_snapshots` with `state_blob` containing invalid JSON (e.g., `"{corrupt"`).  
**When:** `reconstructInstanceWithSnapshot(instance_id)` is called.  
**Then:** The deserialisation fails, the corrupt snapshot is ignored, and the function falls back to full replay, returning the correct state.  
**Layer:** integration  
**Acceptance criterion mapped:** "Corrupt state_blob: If JSON parsing of a snapshot's state_blob fails, the snapshot is treated as absent and full replay is used."
