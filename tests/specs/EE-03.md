# Test Spec: EE-03 — Task activation

**Requirement:** EE-03 — Upon entering a node, the platform SHALL create a Task record with status = PENDING and persist it atomically with the state transition event.  
**Priority:** MUST  
**Test layer:** unit, integration

## Test Cases

| Test Case ID | Acceptance Criterion | Description |
|--------------|---------------------|-------------|
| TC-EE-03-01 | HUMAN_TASK node entry populates `pending_task_nodes` | Entering a HUMAN_TASK node causes `transition()` to add the node ID to `pending_task_nodes`. |
| TC-EE-03-02 | START node entry does NOT add to `pending_task_nodes` | The START node is traversed immediately on `instance_started`; it never appears in `pending_task_nodes`. |
| TC-EE-03-03 | END node entry does NOT add to `pending_task_nodes` | Completing a task that routes to END leaves `pending_task_nodes` empty and sets status = COMPLETED. |
| TC-EE-03-04 | EXCLUSIVE_GATEWAY entry does NOT add to `pending_task_nodes` | An EXCLUSIVE_GATEWAY is evaluated and traversed without producing a pending-task entry. |
| TC-EE-03-05 | PARALLEL_GATEWAY entry does NOT add to `pending_task_nodes` | A PARALLEL_GATEWAY split creates branch tokens but no pending-task entries. |
| TC-EE-03-06 | Task visible via GET /tasks immediately after commit | A Task created by `applyTransition()` is returned by the GET /tasks endpoint as soon as the transaction commits. |
| TC-EE-03-07 | Task record contains required fields | A persisted Task row includes `task_id`, `instance_id`, `node_id`, `assignee_type`, `assignee_ref`, and `created_at`. |
| TC-EE-03-08 | HUMAN_TASK with no `assignee_ref` creates Task in PENDING | When no assignee is configured on a HUMAN_TASK node, the Task is created with `status = PENDING` and null `assignee_ref`. |

---

### TC-EE-03-01: HUMAN_TASK node activation creates Task with status=PENDING
**Given:** A `DefinitionGraph` containing START → HUMAN_TASK, and an `InstanceState` with no tokens.  
**When:** `transition()` is called with an `instance_started` event.  
**Then:** The returned `InstanceState.pending_task_nodes` contains the HUMAN_TASK node ID, and `InstanceState.tokens` has one token parked on that node.  
**Layer:** unit  
**Acceptance criterion mapped:** GIVEN the execution token enters a HUMAN_TASK node, WHEN the transition function produces a new state, THEN the persistence layer creates a Task record with `status = PENDING`.

### TC-EE-03-02: START node activation does NOT create Task record
**Given:** A `DefinitionGraph` containing START → END, and an `InstanceState` with no tokens.  
**When:** `transition()` is called with an `instance_started` event.  
**Then:** The returned `InstanceState.pending_task_nodes` is empty; no task entry is produced for the START node. The instance status is COMPLETED.  
**Layer:** unit  
**Acceptance criterion mapped:** START and END nodes MUST NOT create Task records.

### TC-EE-03-03: END node activation does NOT create Task record
**Given:** A `DefinitionGraph` containing START → HUMAN_TASK → END, and an `InstanceState` with a token on the HUMAN_TASK node.  
**When:** `transition()` is called with a `task_completed` event for that HUMAN_TASK.  
**Then:** The returned `InstanceState.pending_task_nodes` is empty; no task entry is produced for the END node. The instance status is COMPLETED.  
**Layer:** unit  
**Acceptance criterion mapped:** START and END nodes MUST NOT create Task records.

### TC-EE-03-04: EXCLUSIVE_GATEWAY activation does NOT create Task record
**Given:** A `DefinitionGraph` containing START → EXCLUSIVE_GATEWAY → END (default edge), and an `InstanceState` with no tokens.  
**When:** `transition()` is called with an `instance_started` event.  
**Then:** The returned `InstanceState.pending_task_nodes` is empty; the gateway is evaluated and traversed without producing a task entry. The instance status is COMPLETED.  
**Layer:** unit  
**Acceptance criterion mapped:** EXCLUSIVE_GATEWAY and PARALLEL_GATEWAY nodes MUST NOT create Task records.

### TC-EE-03-05: PARALLEL_GATEWAY activation does NOT create Task record
**Given:** A `DefinitionGraph` containing START → PARALLEL_GATEWAY → {END_A, END_B} (two outgoing edges), and an `InstanceState` with no tokens.  
**When:** `transition()` is called with an `instance_started` event.  
**Then:** The returned `InstanceState.pending_task_nodes` is empty; the gateway split creates tokens on END_A and END_B without producing task entries. The instance status is COMPLETED.  
**Layer:** unit  
**Acceptance criterion mapped:** EXCLUSIVE_GATEWAY and PARALLEL_GATEWAY nodes MUST NOT create Task records.

### TC-EE-03-06: Task visible via GET /tasks immediately after commit
**Given:** A process instance has been started and an `applyTransition()` call has committed a HUMAN_TASK activation.  
**When:** `GET /api/v1/tasks` is called immediately after commit.  
**Then:** The response contains the newly created Task with `status = PENDING`.  
**Layer:** integration  
**Acceptance criterion mapped:** A newly created Task is visible to `GET /tasks` immediately after its transaction commits.

### TC-EE-03-07: Task record contains required fields
**Given:** `TaskStore.createInTx()` is called with valid `instance_id`, `token_id`, `node_id`, `node_name`, `assignee_type`, and `assignee_ref`.  
**When:** The INSERT succeeds and the returned `Task` is inspected.  
**Then:** The returned `Task` has non-zero `task_id`, the supplied `instance_id`, `node_id`, `assignee_type`, `assignee_ref`, and a non-zero `created_at`.  
**Layer:** integration  
**Acceptance criterion mapped:** THEN the persistence layer creates a Task record with `task_id`, `instance_id`, `node_id`, `assignee_type`, `assignee_ref`, and `created_at`.

### TC-EE-03-08: HUMAN_TASK with no assignee_ref creates Task in PENDING (group resolution deferred)
**Given:** `TaskStore.createInTx()` is called with `assignee_type = null` and `assignee_ref = null`.  
**When:** The INSERT succeeds.  
**Then:** The returned `Task` has `status = PENDING`, `assignee_type = null`, `assignee_ref = null`.  
**Layer:** integration  
**Acceptance criterion mapped:** Activation of a HUMAN_TASK where `assignee_ref` is null: Task is created in PENDING status; assignment resolution is deferred.
