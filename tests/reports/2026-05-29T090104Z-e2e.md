### 1. TC-PDUI16-01: ConditionDialog shows CodeMirror CEL expression editor

**File:** `web/tests/e2e/f2-canvas-shoulds.e2e.spec.ts:210`
**Severity:** MAJOR
**Error:**

```
expect(locator).toBeVisible() failed

Locator: getByTestId('cel-expression-editor').locator('.cm-placeholder')
Expected: visible
Timeout: 5000ms
Error: element(s) not found
```

**Root Cause Analysis:**

The test asserts that `.cm-placeholder` is a visible DOM element child of the CodeMirror editor container. However, in CodeMirror 6 (used via `@uiw/react-codemirror`), the placeholder text is rendered as an internal decoration/view plugin — it does NOT produce a `.cm-placeholder` CSS class DOM element as a child of the editor container. The placeholder is typically rendered as a `::before` pseudo-element or managed entirely within CodeMirror's virtual DOM.

The `CelExpressionEditor` component passes `placeholder="e.g. status == 'approved'"` to `<CodeMirror>`, and the component's custom theme styles `.cm-placeholder` for the internal CM rendering, but the actual DOM element with class `.cm-placeholder` may not exist in the rendered output the way the test expects.

**Fix guidance:**
- Check for placeholder text visibility using `page.locator('.cm-content').textContent()` or check that the CM editor container has a `[data-placeholder]` attribute
- Alternatively, verify the placeholder renders as a `::before` pseudo-element content via `page.locator('.cm-content')` CSS inspection
- The component passes `placeholder` prop to `@uiw/react-codemirror` which uses CM6's `placeholder` extension — verify how this renders in the DOM

### 2. TC-PDUI16-02: Inline server error display in ConditionDialog

**File:** `web/tests/e2e/f2-canvas-shoulds.e2e.spec.ts:280`
**Severity:** MAJOR
**Error:**

```
Test timeout of 30000ms exceeded.

Error: locator.click: Test timeout of 30000ms exceeded.
Call log:
  - waiting for getByTestId('condition-cancel')
```

**Root Cause Analysis:**

The test opens the ConditionDialog, types `status == ` into the CodeMirror editor, then attempts to click Confirm (if enabled) and check for error display. After that, it tries to click `condition-cancel` to dismiss the dialog, but the cancel button is either not found or the dialog was dismissed earlier.

Likely causes:
1. **CodeMirror input not receiving keyboard events:** The test clicks `.cm-content` then uses `page.keyboard.type('status == ')`, but CodeMirror 6 uses a contenteditable div with custom input handling. `page.keyboard.type()` may not correctly dispatch input events to CodeMirror's internal state, so the expression may remain empty, keeping the Confirm button disabled.
2. **Dialog dismissed by backdrop click:** The `ConditionDialog` component has `onClick={onCancel}` on the backdrop overlay. If any click event propagates to the backdrop (e.g., the `.cm-content` click doesn't stop propagation), the dialog closes before the test can interact with the cancel button.
3. **The expression `status == ` may parse as valid CEL:** If the editor input works correctly, the Confirm button is enabled (`isValid = isDefault || celExpression.trim().length > 0`). Clicking Confirm calls `onConfirm()` which may close the dialog, removing the cancel button from the DOM.

**Fix guidance:**
- Use `page.locator('.cm-content').fill('status == ')` or `page.locator('.cm-content').pressSequentially('status == ')` instead of `page.keyboard.type()` for CodeMirror input
- Add a guard: if dialog is no longer visible after Confirm, skip the cancel button click
- Consider using `cmInput.focus()` before typing to ensure keyboard events reach CodeMirror
