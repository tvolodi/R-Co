## 4. Source Changes (Blockers Fixed)

### `src/engine/instance.zig` — Zig 0.16 API migration

**Bug 1: `std.ArrayList(T).init(allocator)` — 5 sites**

`std.ArrayList` in Zig 0.16 removed the `init(allocator)` constructor; allocator must be
passed per-operation. All five sites in `instance.zig` were updated:

- `apply` → `new_task_nodes`: `.init(allocator)` → `.empty`; `.deinit()` → `.deinit(allocator)`;
  `.append(x)` → `.append(allocator, x)`
- `apply` → `tokens_buf`: `.init(a)` → `.empty`; all `.append`/`.appendSlice` calls take `a`
- `completeTask` → `tokens`: `.init(allocator)` → `.empty`; `.deinit()` → `.deinit(allocator)`;
  `.append(x)` → `.append(allocator, x)`
- `completeTask` → `pending_task_nodes`: same pattern as `new_task_nodes`
- `completeTask` → `tokens_buf`: same pattern as `apply` `tokens_buf`

**Bug 2: `std.crypto.random` removed — 3 sites**

`std.crypto.random` was removed from Zig 0.16's standard library. A `fillRandom(buf: []u8)`
helper was added to `instance.zig` using conditional compilation:
- `.windows` → `advapi32.SystemFunction036` (RtlGenRandom)
- `.linux` → `std.os.linux.getrandom`
- `.macos`, BSD variants → `std.c.arc4random_buf`

All three calls to `std.crypto.random.bytes` (in `create`, `apply`, `completeTask`) were
replaced with `fillRandom`.
