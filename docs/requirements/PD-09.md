# PD-09 — Definition import/export `[SHOULD]`

> The platform SHOULD provide endpoints to export a definition to a self-contained JSON document and to import a previously exported document, enabling migration between environments.

**Acceptance Criteria:**
- GIVEN an authorised caller requests `GET /definitions/{id}/export`, WHEN the definition exists, THEN HTTP 200 is returned with a JSON document containing all definition fields, the full graph, and a `bpm_export_schema_version` field identifying the export format version.
- GIVEN a valid export document, WHEN `POST /definitions/import` is called, THEN HTTP 201 is returned and a new definition is created in DRAFT status with a newly assigned UUID (the imported UUID is not re-used).
- GIVEN an import document with a `bpm_export_schema_version` not supported by the current platform, THEN HTTP 422 is returned identifying the unsupported version.
- An imported definition MUST pass the same graph and attribute validation as PD-02 and PD-05.
- Import MUST be idempotent based on name+version: if a definition with the same name and version already exists, HTTP 409 is returned.

**See:** PD-01 (import is treated as a create with external data), PD-02 (validation still applies), PD-05 (node attribute validation still applies)

**Edge cases:**
- Export document manually edited by the user: parsed normally; if validation fails, HTTP 422 lists all errors.
- `bpm_export_schema_version` absent from import payload: rejected with HTTP 422.
