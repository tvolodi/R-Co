# PD-05 — Node types `[MUST]`

> The platform SHALL support node types START, END, HUMAN_TASK, SERVICE_TASK, EXCLUSIVE_GATEWAY, PARALLEL_GATEWAY, and TIMER. Each type SHALL have mandatory and optional attribute schema that is validated at definition-save time.

**Acceptance Criteria:**
- GIVEN a node with `type = HUMAN_TASK`, WHEN the definition is saved, THEN the node MUST have a `role` attribute (non-empty string); absence is rejected with HTTP 422.
- GIVEN a node with `type = SERVICE_TASK`, WHEN the definition is saved, THEN the node MUST have an `endpoint` attribute (non-empty string URL) and a `timeout_ms` attribute (positive integer ≤ 300,000); violations are rejected with HTTP 422.
- GIVEN a node with `type = TIMER`, WHEN the definition is saved, THEN the node MUST have a `duration_iso8601` attribute containing a valid ISO 8601 duration string; invalid strings are rejected with HTTP 422.
- GIVEN a node with `type = EXCLUSIVE_GATEWAY` or `PARALLEL_GATEWAY`, WHEN the definition is saved, THEN no mandatory additional attributes are required (gateway role is defined by topology).
- GIVEN a node with `type = START` or `type = END`, WHEN the definition is saved, THEN no additional attributes are required.
- Any node with an unrecognised `type` value MUST be rejected with HTTP 422 listing the invalid type.

**See:** PD-02 (structural graph validation runs first), PD-06 (edge condition validation on EXCLUSIVE_GATEWAY outbound edges), EE-03 (task activation uses role attribute), EE-05 (gateway evaluation uses topology)

**Edge cases:**
- `timeout_ms = 0`: rejected (must be positive).
- `duration_iso8601 = "P0D"` (zero duration): permitted; fires immediately.
- Extra undeclared attributes on a node: ignored (forward-compatibility).
