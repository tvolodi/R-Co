# PD-06 — Edge conditions `[MUST]`

> Edges originating from EXCLUSIVE_GATEWAY nodes SHALL carry a CEL expression condition or be marked as the default (fallback) edge. The platform SHALL validate CEL syntax at definition-save time. At most one default edge per gateway is allowed.

**Acceptance Criteria:**
- GIVEN an EXCLUSIVE_GATEWAY with outgoing edges, WHEN the definition is saved, THEN every edge either has a non-empty `condition` (valid CEL string) or has `is_default = true`; edges with neither are rejected with HTTP 422.
- GIVEN an EXCLUSIVE_GATEWAY with more than one edge marked `is_default = true`, THEN HTTP 422 is returned.
- GIVEN an edge condition containing syntactically invalid CEL, WHEN the definition is saved, THEN HTTP 422 is returned identifying the edge and the syntax error.
- GIVEN an EXCLUSIVE_GATEWAY with no default edge and instance variables that satisfy none of the conditions at runtime, THEN the execution engine routes to the DLQ (per OBS-05) and sets the instance status to ERROR.
- Non-gateway node outgoing edges MUST NOT have `condition` or `is_default`; such edges are rejected with HTTP 422.

**See:** PD-05 (EXCLUSIVE_GATEWAY node type), EE-05 (runtime evaluation of conditions), PD-02 (structural validation runs before edge condition validation)

**Edge cases:**
- Edge with `condition = ""` (empty string): treated as absent → rejected.
- `is_default = false` explicitly set: equivalent to not set; the edge needs a condition.
- PARALLEL_GATEWAY outgoing edges: no conditions allowed (all branches always activated).
