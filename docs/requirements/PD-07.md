# PD-07 — Definition retrieval `[MUST]`

> The platform SHALL provide endpoints to: (a) retrieve a definition by UUID; (b) list definitions with pagination and optional filters (name, status, stage); (c) retrieve the currently ACTIVE version by definition name.

**Acceptance Criteria:**
- GIVEN a valid UUID, WHEN `GET /definitions/{id}` is called, THEN HTTP 200 is returned with the full definition including graph, status, and metadata. GIVEN an unknown UUID, THEN HTTP 404.
- GIVEN a request to `GET /definitions`, WHEN called without filters, THEN all definitions are returned paginated (default page size per API-06, up to configured max).
- `GET /definitions` MUST support `?name=`, `?status=`, and `?stage=` query-parameter filters; each is optional and combinable.
- GIVEN a definition name N, WHEN `GET /definitions/active/{name}` is called and an ACTIVE version exists, THEN HTTP 200 is returned. GIVEN no ACTIVE version, THEN HTTP 404.
- Pagination parameters (`page`, `page_size`) MUST be validated per API-06.

**See:** API-06 (pagination), API-07 (input validation applies to query parameters), API-08 (auth required)

**Edge cases:**
- `?status=` filter with an unrecognised status value: rejected with HTTP 422.
- Listing definitions when no definitions exist: returns HTTP 200 with an empty array.
