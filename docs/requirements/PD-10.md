# PD-10 — Definition search `[COULD]`

> The platform COULD provide full-text search over definition names and descriptions, returning ranked results.

**Acceptance Criteria:**
- GIVEN a search query string, WHEN `GET /definitions/search?q={query}` is called, THEN HTTP 200 is returned with a ranked list of definitions whose name or description contains the query terms.
- Results MUST be ordered by relevance (highest-scoring first).
- An empty query (`q=`) MUST be rejected with HTTP 422.
- Pagination MUST be supported per API-06.
- Search MUST be case-insensitive and SHOULD support partial word matching.

**See:** PD-07 (basic listing with filters; search is an extension), API-06 (pagination applies), API-07 (input validation)

**Edge cases:**
- Query that matches no definitions: HTTP 200 with empty array.
- Query containing SQL-special characters: handled safely (no injection possible).
- Very long query string (> 512 characters): rejected with HTTP 422.
