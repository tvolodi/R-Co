# PD-04 — Definition lifecycle `[MUST]`

> Definitions SHALL follow the lifecycle: DRAFT → ACTIVE → DEPRECATED → ARCHIVED. Transitions in the reverse direction are forbidden. ARCHIVED is a terminal state; DEPRECATED definitions may still be referenced by running instances.

**Acceptance Criteria:**
- GIVEN a DRAFT definition, WHEN an activate request is made, THEN the definition transitions to ACTIVE.
- GIVEN an ACTIVE definition, WHEN a deprecation request is made (or superseded by PD-03), THEN the definition transitions to DEPRECATED.
- GIVEN a DEPRECATED definition, WHEN an archive request is made, THEN the definition transitions to ARCHIVED.
- No transition other than those above is permitted; any other transition attempt MUST be rejected with HTTP 409 describing the invalid transition.
- GIVEN an ARCHIVED definition, WHEN any modification (update, re-activate, re-deprecate) is attempted, THEN HTTP 409 is returned.
- Existing instances referencing a DEPRECATED definition MUST continue running to completion; the platform MUST NOT terminate them due to the deprecation.
- New instances MUST NOT be started from a DEPRECATED or ARCHIVED definition; only ACTIVE definitions may be used to start an instance.

**See:** PD-03 (DRAFT → ACTIVE triggers deprecation of prior ACTIVE version), PD-08 (snapshot means a definition's archival does not affect running instances), EE-01 (instance start requires ACTIVE definition)

**Edge cases:**
- Attempting to archive an ACTIVE definition directly (skipping DEPRECATED): rejected.
- Attempting to archive a DRAFT: rejected.
