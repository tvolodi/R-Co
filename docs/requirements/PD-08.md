# PD-08 — Definition snapshot `[MUST]`

> When a new process instance is started, the platform SHALL store an immutable copy (snapshot) of the definition graph at that moment. Subsequent modifications or archival of the definition MUST NOT affect running instances.

**Acceptance Criteria:**
- GIVEN a process instance is started from definition version V, WHEN the definition V is later modified or its status changes, THEN the running instance continues to execute against the original snapshot captured at start time.
- The snapshot MUST include the full graph (nodes, edges, all attributes) as it existed at the moment `POST /instances` was processed.
- GIVEN an instance's definition snapshot is requested (e.g. `GET /instances/{id}/definition`), THEN the snapshot as stored at start time is returned, not the current definition.
- Snapshot storage MUST be atomic with the instance-creation transaction; partial snapshots MUST NOT be observable.

**See:** EE-01 (instance start triggers snapshot), PD-04 (archival does not kill running instances due to snapshot), DB-03 (snapshot and instance creation in one transaction)

**Edge cases:**
- Definition is ARCHIVED before all its instances complete: existing instances use their snapshot and complete normally.
- Two instances started microseconds apart from the same definition version: each has its own independent snapshot row.
